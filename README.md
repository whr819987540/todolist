# 待办清单

基于 Tauri 2 + React + Ant Design 的 Windows 桌面待办管理软件，按「工作区 → 项目 → 待办」三级组织，项目下还可以建子项目，子项目里还能再建，层数不限。

下载：[最新版](https://github.com/whr819987540/todolist/releases/latest)的 `TodoList_<版本>_x64-setup.exe`（只装给当前用户，不需要管理员权限），见下文「发布到 GitHub」。0.1.2 起装好后会自己检查更新，有新版本时提示、点一下就更新；0.1.1 及以前的版本要再下载安装包覆盖安装一次。

## 功能

- **三级结构**：首页列出全部工作区；进入工作区后左侧是可折叠的树（工作区、项目两级都能折叠），右侧显示概览或待办内容
- **子项目**：右键项目（或项目概览、侧栏顶部的「新建」）选「新建子项目」，在项目下再分一层，子项目里还能再建，层数不限；父项目自己也能直接放待办。子项目就是项目文件夹里的子文件夹，在侧栏里每多一级缩进一级、列在父项目下面、它自己的待办前面，各级各自可以折叠；层级多时缩进逐渐变小，侧栏窄时少缩进几级（再深的在文件夹图标上标出是第几级），展开着的项目下面有一条竖线连起它下面的东西，名字放不下时显示省略号、悬停看完整路径；编辑区上方、项目概览上方的路径放不下时中间折叠成「…」（悬停列出折叠掉的几级），提示、菜单里的路径太长时也中间折叠。项目的未完成数、完成进度包括各级子项目里的待办，项目概览上面列出下一级子项目的卡片；父项目改名后下面各级、标签、编辑位置都跟着走，删除项目连同下面各级一起进回收站；在左侧列表里按 ← 回到上一级。层级多、名字长时路径可能超过 Windows 的上限（260 个字符），新建、改名、移动前会检查并提示
- **进入工作区**：从首页点进某个工作区时，直接打开上次在这个工作区打开的待办；还没打开过待办时显示工作区概览
- **拖动移动**：按住左侧列表或项目概览里的待办，拖到左侧的另一个项目上松开，就移到那个项目里；同时显示了几个工作区时，也能拖到其他工作区的项目里。按住左侧列表或概览里的项目，拖到左侧的另一个项目（哪一级的子项目都行）上，放进去成为它的子项目；拖到工作区那一行上，移到这个工作区的顶层（子项目这样移出来），都可以跨工作区，整个项目连同待办和下面各级子项目移过去（那里已有同名项目、放进它自己的子项目里时不能放）。右键项目的「移动到」能去的地方一样。拖到折叠起来的工作区上停一会儿会自动展开，拖到列表上下边缘会自动滚动，按 Esc 取消
- **开屏**：打开软件时默认显示首页；在「设置 → 常规」里可改成「回到上次的位置」，恢复上次左侧选中的工作区和右侧打开的待办（下次启动时生效）
- **同时查看多个工作区**：点侧栏顶部的工作区名，勾选要显示的工作区（可多选、全选，或「仅显示」某一个），左侧会同时列出这些工作区的项目和待办；选中的工作区会记住，下次进入时恢复
- **后退 / 前进**：用鼠标侧键的后退键、前进键在看过的地方之间来回（首页、工作区概览、项目概览、待办），和浏览器一样；只记这次运行期间的
- **键盘操作**：Alt+← / → 在左侧列表和右侧编辑区之间切换，Alt+↑ / ↓ 在左侧的工作区、项目、待办之间上下移动；焦点在右侧的待办里时，Alt+← / → 切到左边 / 右边的标签（最左边的标签上 Alt+← 仍回到左侧列表，最右边的标签上 Alt+→ 仍把焦点放进正文），Alt+↑ 关掉这个标签
- **标签页**：右侧上方一排标签，可以同时打开多条待办，点标签来回切换，切回来时光标、选中的文字、滚动位置都和离开时一样，焦点直接在正文里，接着打字就行
  - 和 VS Code 一样：单击（或用方向键移到）的待办先开在「预览」标签里（标题斜体），再打开别的会替换它，浏览列表时标签不会越开越多；改了标题或正文、双击左侧的待办、双击标签后一直留着。新建的待办直接开在固定的标签里
  - Ctrl+Tab / Ctrl+Shift+Tab 切到下一个 / 上一个标签；×、鼠标中键或 Ctrl+W 关掉（先保存），右键标签可以关闭其他的、右侧的、全部；按住标签左右拖动调整顺序（Esc 取消）；有没保存的修改时标签上 × 的位置显示圆点
  - 打开着哪些标签记在数据目录里，下次打开软件还在；工作区 / 项目改名、待办移动后跟着走，删除后关掉。只显示侧栏里选中的工作区的标签
- **分屏**：按 Alt+Shift++（+ / = 键）左右分屏、Alt+Shift+- 上下分屏（或点标签栏右端的分屏按钮、右键标签），右侧分成两边，各有一排标签，各自打开任意待办，同 VS Code 的编辑器组
  - 新的一边先显示正在编辑的待办；左侧列表、搜索结果、后退 / 前进和新建的待办打开在有焦点（最后点过）的那一边；同一个方向再按一次合并回一边，按另一个方向改成那个方向
  - 同一条待办可以两边都开着：一边改了另一边马上跟着变，只存一次、不会互相覆盖，撤销记录共用；光标、滚动、查找框、编辑模式各边各自的（可以一边看源码、一边看实时渲染）
  - 按住标签拖到另一边的标签栏或编辑区里（或右键标签「移到另一边」），就移到那一边；一边的标签都关掉（拖走）后这一边消失；中间的分隔条可以拖动调整比例，双击恢复一半一半；Alt+← / Alt+→ 在两边的标签之间连着切（左边一边最右边的标签上 Alt+→ 进入右边一边）
  - 分屏的方向、比例、两边的标签记在数据目录里，下次打开软件还在；窗口太窄放不下左右两边时自动改成上下排
- **待办条目**：左侧显示标题；没有标题时显示正文开头（按侧栏宽度自动截断）。每条带完成勾选框、创建时间、最新修改时间，悬停可看完整时间
- **批量操作**：在左侧列表里 Ctrl+单击加选、Shift+单击选中一段，右侧显示批量操作：一起标记完成 / 未完成、置顶、设置优先级、添加 / 移除标签、移动到其他项目、删除；也可以右键选中的待办，或把它们一起拖到左侧的其他项目上。Esc 取消选择，Delete 删除
- **回收站**：删除的工作区、项目、待办先放进软件的回收站，删除后的提示里可以「撤销」；首页头部或侧栏底部的「回收站」里可以恢复到原来的位置（原来的项目、工作区不在了会重新建，名字被占用了加「（恢复）」）、彻底删除或清空。放满 30 天的、彻底删除的移到 Windows 回收站
- **完成记录**：首页头部或侧栏底部的「完成记录」按完成日期列出完成了的待办（各级子项目里的都算，位置是「工作区 / 父项目 / 子项目 / …」，层级多时中间折叠）——今天、昨天，再往前按日期（「10月7日 星期三」），组里后完成的在前，以前的版本没记下完成时间的在最后的「完成时间不详」；每条带着优先级的小旗子和标签（同侧栏）；上面是时间范围（最近 7 天 / 30 天 / 全部，记在本机）、按标题、项目和标签查找（`#标签名` 只按标签找）、今天和这个范围里完成了几条，以及每天完成几条的柱状图（点一根跳到那天）。点一条进入它所在的工作区打开它（同搜索结果：开在分屏时有焦点那一边的预览标签里，展开它所在的各级项目），右键或行上的按钮「标记为未完成」。首页上看全部工作区；侧栏里默认看选中的工作区，可以切到全部工作区
- **导出**：右键待办（或分屏两边编辑区上方的「…」）、项目（哪一级的子项目都行）、工作区选「导出」→「导出为 HTML」或「导出为 PDF」。HTML 是一个文件：标题、状态、优先级、标签、所在的位置、时间和渲染后的正文（表格、任务框、代码块、脚注等，正文里写的 HTML 做了安全处理），本地图片（各级项目里的 `.assets\{待办 id}\`）嵌在里面，拿到别的电脑上也能看。导出项目、工作区时有封面（待办数、完成进度，连同各级子项目）和可以点的目录，按项目的层级分章：项目自己的待办在前，各级子项目依次作为下一级的章（标题一级级加深，最深到 h6；深的章前面用灰色小字写着它外面那几章），目录一层层缩进；每一层的项目和待办的顺序同侧栏（项目手动排序、待办按优先级排时也一样），可以选不含已完成的。总是浅色、A4 宽度，打印时每条待办、每章从新的一页开始（自己没有待办的章，第一个子项目接在它的标题后面）。PDF 是用系统的 WebView2 把同样的内容打印出来的（A4，页眉是日期和标题，页脚是页码，网上的图片要联网才印得出来；WebView2 太旧、直接存不成时退回系统的打印对话框，在里面选「另存为 PDF」）。导出前先存盘（分屏两边开着的都存）；默认文件名是标题或项目的各级（「需求 - 前端 - 组件」），从上次导出到的目录（第一次是「文档」）打开
- **筛选**：侧栏顶部的漏斗按钮（「隐藏已完成」旁边）按标签、优先级筛选：列出侧栏里显示的工作区用到的全部标签和各档优先级（都带条数），可以多选，标签之间「任一」或「全部」；开着时侧栏和项目概览只列符合的待办、没有符合的项目不显示（右侧正在看的照常显示），顶部一行写明筛的是什么，点 × 清除。点侧栏、项目概览、编辑区上方的标签就按它筛选。和搜索、隐藏已完成可以一起用；只记在这次运行期间，筛选时不能拖动调整顺序。弹出框里每个标签后面的「…」可以重命名（改成已有的名字就是合并）、删除这个标签，作用于侧栏里显示的各工作区
- **置顶**：右键待办选「置顶」，它就排在所在项目的最前面（已完成的仍沉底），标题前有图钉
- **优先级**：每条待办可以设成高 / 中 / 低（默认无）：在编辑区上方的下拉、右键「优先级」或多选后「设置优先级」里改；侧栏和项目概览里标题前面显示小旗子（高红、中橙、低蓝），排序按钮里可以「按优先级」排（置顶的仍在前、已完成的仍沉底）。改优先级不算修改，移动后还在
- **标签**：给待办加上「工作」「等回复」这样的标签（可以有多个），跨项目、跨工作区归类：在编辑区上方点「+ 标签」输入（从用过的标签里联想），或右键待办选「标签…」；侧栏和项目概览里标题后面显示彩色的小标签，同名的标签颜色相同。搜索时也匹配标签名，输入 `#标签名` 只按标签找；点标签按它筛选（见「筛选」）；多选后可以批量添加、移除标签。改标签不算修改，移动、恢复后还在
- **手动排序**：在左侧列表或项目概览里把待办拖到同一项目的另一条待办上方 / 下方，调整它的位置，这个工作区随即改成手动排序（排序按钮里可以换回）；新建的待办排在最前面
- **项目的顺序**：项目默认按名字排；在左侧列表里把项目（或哪一级的子项目）拖到另一个项目那一行的上沿 / 下沿，就放在它前面 / 后面（插入线标出位置），这个工作区的项目随即改成手动排序；每一层（顶层、各级项目里的子项目）各排各的，子项目总跟着它的父项目。拖到别的一层（子项目拖到两个顶层项目之间、项目拖到别的项目的两个子项目之间、跨几级拖到深处、拖到别的工作区的项目旁边）是移过去放在那里，有子项目的连同下面各级和它们的顺序一起过去；拖到行中间照常是放进去成为子项目。新建的、移进来时没指定位置的排在后面，改名后位置不变；排序按钮里「项目顺序」可以换回按名称（顺序留着，换回手动排序时恢复）。顺序记在数据目录里（每一层一个 `.projects.json`），网盘同步、换电脑都跟着走；概览的卡片、「移动到」、快速记录选项目的列表也按这个顺序
- **正文编辑**：右侧编辑 Markdown；右键待办可「用默认程序打开」，交给系统关联的 Markdown 软件
  - **实时渲染**（默认，类似 Typora）：标题、加粗、斜体、删除线、下划线、行内代码、链接、图片、表格、引用、列表、任务框、分隔线、代码块显示成渲染后的样子，光标移到哪里，哪里显示原文；点任务框直接勾选。列表和 Typora 一样每级缩进约两个字宽，一项太长折行时折下来的行和第一行的正文开头对齐；光标碰到列表符号、引用的 > 显示原文时，文字不左右跳；整段划掉（`~~…~~`）的列表项，序号、列表符号也一起划掉（文件里照原样）
  - **源码模式**：显示全部 Markdown 标记，只做语法高亮；列表的缩进照原样的空格，折行后同样对齐到正文开头
  - 按 Ctrl+/ 或点状态栏上的「实时渲染 / 源码模式」切换，每条待办分别记住；没切换过的待办用实时渲染（以前的版本里选了源码模式的，沿用源码模式）。两种模式都只改变显示，文件按原样保存，不会被重新排版
  - **表格**（GFM 表格）：实时渲染时光标不在表格里，整个表格显示成渲染后的样子（表头加粗，按 `:---:` 这类分隔行对齐，格子里的加粗、行内代码、链接、图片也渲染），很宽的在编辑区里横向滚动、不把编辑区撑宽；单击格子光标放进那一格的原文里，表格显示原文以便修改；分屏时两边各按自己的光标显示。列表、引用里的表格显示原文；按 Ctrl+T 插入一个空表格
  - **图片**：在正文里 Ctrl+V 粘贴截图、从浏览器复制的图片，或者从资源管理器把图片文件拖进来（拖动时有一条竖线标出放在哪里；分屏时拖到哪一边就插进哪一边），复制一份存在项目文件夹的 `.assets\{待办 id}\` 里，正文里写成相对地址 `![说明](.assets/…)`，用 Typora、VS Code 打开 .md 也能显示。实时渲染时显示成图片（宽的缩到编辑区的宽度，显示不了的写明原因），光标所在的那一行显示原文；别处的本地图片（相对路径、绝对路径）和网络图片也能显示。图片跟着待办移动、进出回收站，「另存为新待办」时复制一份；项目很深、图片的路径太长时名字截短，再放不下时不插入
  - 按住 Ctrl 单击链接用浏览器打开；回车自动续写列表；在列表里按 Tab / Shift+Tab 把这一项（连同子项）缩进成上一项的子项 / 提到上一级，有序列表自动重新编号；不在列表里时 Tab 插入两个空格
  - **编辑快捷键**默认和 Typora 一样：Ctrl+B 加粗、Ctrl+I 斜体、Ctrl+U 下划线、Ctrl+K 超链接、Ctrl+1～6 标题、Ctrl+Shift+[ / ] 有序 / 无序列表、Tab / Shift+Tab 缩进列表、Ctrl+D 选中当前词等，完整列表见下文「快捷键」；都可以在「设置 → 快捷键」里改成自己习惯的按键。再按一次取消；只增删选中处的 Markdown 标记，不会重排别处的写法
  - **大纲**：正文里有 2 个以上标题时，右侧列出标题，点一下跳过去，正在看的那一节高亮；点状态栏的「大纲」或按 Ctrl+Shift+1 显示 / 隐藏
  - **查找 / 替换**：按 Ctrl+F 在正文里查找，输入时直接跳到最近的结果，显示第几个 / 共几个，Enter / Shift+Enter（或 F3 / Shift+F3）找下一个 / 上一个，可以区分大小写、全字匹配、用正则；Ctrl+H 展开替换，逐个或全部替换；Esc 关闭查找框
  - 切换回某条待办时，光标和滚动回到上次编辑的地方，离开时选中的文字仍然选中；正文在外部被改过时按光标前后的文字找回位置，被大幅修改、找不到时回到开头
  - 切到别的待办再切回来，仍能用 Ctrl+Z / Ctrl+Y 撤销、重做之前的修改（只在这次运行期间；正文在外部被改过时从头记起）
  - 代码块：输入 ```语言 后回车会自动补上结尾的 ```；在代码块里按 Ctrl+Enter，或在文末代码块的最后一行按 ↓，跳出代码块（缺结尾的 ``` 时自动补上）
- **保存**：在「设置 → 保存」里修改，立即生效
  - auto save（默认关闭）：开启后，编辑器失去焦点、窗口失去焦点（包括隐藏到托盘）时立即保存，有修改时还定时保存（默认 3 分钟，可设 1 秒到 60 分钟；从第一处未保存的修改开始计时，继续输入不会推迟）
  - 不论开没开，Ctrl+S 立即保存，切换待办、从托盘退出前总会保存（存不上时自动另存为新待办，见下文「外部修改感知」），重命名、移动、删除、用默认程序打开前也总会先保存（存不上时先不做，等你处理完冲突对话框或保存失败的问题）
  - 关闭 auto save 时，失去焦点、隐藏到托盘都不保存；但修改后一直没保存的，满 1 小时会自动保存一次（从第一处未保存的修改开始计时，藏在托盘里时也照样），免得在托盘里挂好几天的程序把改动一直留在内存里
  - 用输入法打字时，拼音还没上屏不算修改，不会被存进文件
- **托盘常驻**：点窗口的关闭按钮只会隐藏到系统托盘，程序继续运行；左键单击托盘图标恢复窗口，右键托盘图标选「退出」才真正退出（会先保存正在编辑的内容；有修改存不下来时不退出，先问你）
- **开机自启**：在「设置 → 常规」里打开，登录 Windows 后自动运行，默认只在托盘里、不弹出主窗口（可以改成显示）；只对这台电脑生效，在任务管理器的「启动应用」里也能关掉，卸载时自动删掉启动项
- **全局快捷键**：默认 Ctrl+Alt+T，在任何程序里按下都能呼出主窗口，主窗口在前台时按下则隐藏到托盘；点右上角的设置按钮可修改、恢复默认或不使用
- **自动更新**：启动后和每隔 6 小时检查 GitHub 上有没有新版本，有了在右下角提示新版本和更新说明，点「立即更新」下载、保存正在编辑的内容后自动安装并重新打开（不会自己安装）；在「设置 → 常规」里可以手动检查更新、关掉自动检查。待办数据和设置都不动
- **虚拟桌面**：主窗口留在另一个虚拟桌面上时，在当前桌面按快捷键、点托盘图标呼出它，会把它挪到当前桌面，不会把你切回原来的桌面。想让它在每个桌面上都在：按 Win+Tab，右键它的缩略图，选「在所有桌面上显示此应用的窗口」
- **快速记录**：在任何程序里按 Ctrl+Alt+N（或托盘菜单的「快速记录」）弹出一个小输入框，第一行写标题、后面写正文，Enter 存进「收件箱 / 快速记录」（不在时自动建，可以改成别的项目），Ctrl+Enter 存好后在主窗口里打开；Esc 或点到别处关掉，没存的留着
- **待办快捷键**：选中某条待办时，Ctrl+Alt+D 标记完成 / 未完成，Ctrl+Alt+O 用默认程序打开；同样可在设置里修改
- **数据备份**：在「设置 → 备份与恢复」里把全部待办数据（各工作区、各级项目和子项目、待办正文、项目的顺序、图片的附件目录和界面状态，不含回收站、设置和密码）打包成 `TodoList-data-年月日-时分秒.zip`，存到本地或上传到 WebDAV；恢复时选本地的备份 zip 或 WebDAV 上的数据备份，确认后先保存打开着的待办（分屏时两边的；有存不上的就不恢复），再用备份替换现在的全部待办数据（替换前先把现在的自动备份成 `…-恢复前.zip`，回收站不动），界面重新加载
  - **自动备份**（默认开启）：启动时和运行期间（藏在托盘里也照常）检查，距上次满 24 小时、数据有变化时备份到 `%USERPROFILE%\TodoList-backups`（可以换目录），只留最近 10 份（可设 1–100），可以同时上传到 WebDAV；失败了不弹窗，在设置里显示原因
- **设置备份**：在「设置 → 备份与恢复」里把设置打包成 `TodoList-settings-年月日-时分秒.zip`，可以存到本地（默认存在数据目录里，也可以另选位置），也可以上传到 WebDAV 服务器（如坚果云）；恢复时可从服务器上的备份列表选择，也可选择本地的备份 zip（默认从数据目录里找，从 WebDAV 下载的也行）。备份只含设置（包括改过的快捷键、自动备份的设置），不含待办数据；拿错了数据备份时会提示
- **字号**：在「设置 → 外观」里分别调整左侧列表（工作区、项目与待办）和右侧待办编辑区的字号，立即生效；编辑时按住 Ctrl 滚动鼠标滚轮可快速调整编辑区字号，点状态栏上的字号恢复默认
- **主题**：浅色、深色或跟随系统（默认），点首页或侧栏顶部的主题按钮、或在「设置 → 外观」里切换，窗口标题栏跟着变
- **编辑区背景色**：待办编辑区默认是护眼米色，可在「设置 → 外观」里换成白色，或选「自定义」输入 RGB 数值设置任意颜色；深色模式下编辑区始终是深色背景
- **全局搜索**：首页可跨全部工作区搜索（Ctrl+Shift+F）工作区、项目和待办（标题与正文全文，命中在正文里的显示关键字附近的一段），点击结果直接打开
- **外部修改感知**：运行期间监听数据目录，网盘同步下来的、别的程序保存的、在资源管理器里增删改名的，窗口一直在前台时也在半秒左右自动刷新（侧栏、首页、概览和打开着的待办；藏在托盘里时等显示出来再刷新），切回窗口时也会刷新；软件自己保存时不会因此重新加载。打开着的待办没有未保存的修改时直接换成外部的内容（光标留在原来那段文字处）；若两边同时改了同一条，立即弹窗让你选择：放弃自己的修改重新加载、用自己的内容覆盖，或「另存为新待办」——两份都保留，你的修改存成同一项目里标题带「（我的版本）」的新待办并打开它，原来这条换成外部改过的内容（外部只是把同样的内容重写了一遍时什么都不做）。没来得及选就切到别的待办、关了标签（分屏时两边都开着它的，两边都关掉才算）、退出了，或者切走时才发现外部改过、待办或项目在外部被删了，会自动另存为「（我的版本）」的新待办并提示它的标题（原来的项目不在了时存到快速记录存到的项目），不会悄悄丢掉
- **隐藏已完成**：侧栏顶部的眼睛按钮里，「隐藏已完成的待办」和「隐藏全部完成的项目」（里面有待办而且全都完成了的项目，连同其中的待办不显示；空项目不算）各自开关，每个工作区各自记住。右侧正在看的项目不藏，切走 1 秒后才藏（比双击间隔长，在它下面的项目里双击时下面的行不会在两下之间上移）；搜索时不藏；工作区下面显示「已隐藏 N 个全部完成的项目，显示」。只影响侧栏，工作区概览、「移动到」等照常列出全部项目
- 侧栏搜索（Ctrl+Shift+F，在选中的工作区里查找标题和正文全文）、隐藏已完成、五种排序（创建时间、修改时间、标题、优先级、手动）（这两项每个工作区各自记住，选中多个工作区时作用于右侧正在显示的那个；排序按钮里还有项目的顺序：按名称 / 手动排序）、在项目间移动待办（右键「移动到」，同时显示了几个工作区时按工作区分组列出它们的项目，和拖动一样能移到其他工作区）、侧栏宽度可拖动

## 数据存储

所有数据保存在用户目录下的 `%USERPROFILE%\TodoList`：

```text
TodoList\
  {工作区}\
    {项目}\
      .todos.json            标题、完成状态、置顶、标签、优先级、手动排序的位置、创建/修改/完成时间
      20260926-153012.md     待办正文，一条待办一个文件
      .assets\               正文里的图片（粘贴、拖进来的），一条待办一个子目录：.assets\{待办 id}\{文件名}
      .projects.json         有子项目时：下一级子项目的顺序（手动排序时）
      {子项目}\              项目文件夹里的子文件夹是子项目，里面同样是 .todos.json、.md、.assets 和 .projects.json，还可以再有子项目（层数不限）
    .projects.json           顶层项目的顺序，和这个工作区的项目是不是手动排序
  .settings.json             应用设置（快捷键和改过的编辑快捷键、主题、字号、编辑区背景色、保存方式、开屏方式、开机自启时是否显示主窗口、快速记录存到哪个项目，自动备份的开关、目录、份数、是否上传 WebDAV），设置备份的内容就是这个文件
  .webdav.json               WebDAV 服务器地址、用户名、远程目录（密码存在 Windows 凭据管理器）
  .state.json                界面状态：选中的工作区、上次的位置、各工作区上次打开的待办、右侧打开着的标签（分屏时两边各自的）、各待办的编辑位置和编辑模式
  .recycle\                  软件的回收站，删除的东西先放在这里，30 天后移到 Windows 回收站
    20261004-153012-123\     一项一个目录：entry.json（原来在哪里、待办的标题和完成状态等）和删除的文件 / 目录（待办的图片在 .assets\{待办 id}\ 里）
  TodoList-settings-*.zip    设置备份到本地时默认存在这里（选择恢复文件时也从这里开始找）
  .restoring-年月日-时分秒\  恢复待办数据时的临时文件夹（解压出来的备份 new、换下来的原来的数据 old、换之前写下的记录 journal.json），恢复完就删掉；替换中途软件退出了的，下次启动时凭记录换回原来的数据（或做完收尾）再删
TodoList-backups\            待办数据的自动备份（数据目录旁边，可以在设置里换别的目录），手动备份、恢复数据的对话框也从这里打开
  TodoList-data-20261009-153012.zip           一份数据备份：各工作区文件夹和 .state.json，外加说明 backup.json
  TodoList-data-20261009-153012-2.zip         同一秒里后存的一份加编号，编号大的算新的（按数比，-10 比 -9 新）
  TodoList-data-20261009-160000-恢复前.zip    恢复数据前自动备份的原来的数据，不算在「保留最近 N 份」里
```

- 标题单独存在 `.todos.json` 里，正文存在 `.md` 文件里
- `.todos.json` 里每条待办一项：`id`（就是 .md 的文件名）、`title`、`done`、`createdAt` / `updatedAt` / `doneAt`，和只在用到时才写的 `pinned`（置顶）、`tags`（标签，如 `["工作", "等回复"]`）、`priority`（优先级：高 3、中 2、低 1）、`order`（手动排序的位置）。置顶、标签、优先级、顺序不算修改，改了不变修改时间；手改得不合规则的标签、优先级读的时候去掉
- 直接往项目文件夹里放 `.md` 文件，软件会自动识别为新待办（文件名作为标题）；在项目文件夹里建文件夹就是建子项目（子项目里的文件夹也是，层数不限；`.` 开头的不算）
- 项目的顺序每一层一个 `.projects.json`，放在那一层的文件夹里（工作区文件夹里的是顶层项目的，哪一级的项目文件夹里的是它下一级子项目的，层数不限），如 `{"version": 1, "manual": true, "order": ["需求", "日常"]}`：`order` 是项目的名字从前到后（不分大小写，没列出的排在后面），`manual` 只看工作区文件夹里的，是这个工作区的项目手动排序（换成按名称时顺序留着）。没调整过顺序时没有这个文件；手改坏了的当成没有，照常按名字排。改名、移动、删除、恢复项目时跟着改（项目里面各级子项目的顺序跟着它走，从按名称排的工作区移到手动排序的工作区时除外），不算修改（工作区文件夹的修改时间也放回去，首页卡片的「更新于」不变）
- 正文里粘贴、拖进来的图片存在待办所在的项目（或哪一级子项目）文件夹的 `.assets\{待办 id}\` 里（拖进来的保留原名，粘贴的叫 `图片-年月日-时分秒.png`），正文里写成相对于 .md 的地址。附件目录不算子项目，里面的 .md 不算待办。移动待办时附件目录跟着走（目标项目里重名、换了 id 时目录改成新 id，正文里的链接跟着改，.md 的修改时间不变）；删除时连同 .md 放进回收站的同一项；「另存为新待办」时复制一份给新的那条。显示本地图片经 Tauri 的 asset 协议：数据目录整个放开，数据目录以外的图片在正文里用到时只放开那一个文件（只放开图片）
- 界面状态、标签、快速记录存到哪里等处记的项目是路径：顶层项目是名字，下一级用 `/` 连起来（「父项目/子项目/…」）
- 完整路径（连同数据目录，按 UTF-16 算字数）不超过 227 个字符：Windows 的资源管理器、默认程序、系统回收站多半打不开超过 259 个字符的路径，删除后放进软件的回收站时路径还会长 32 个字符。新建项目时项目文件夹还要留出 22 个字符给待办文件名；移动、改名（项目、工作区）、移动待办、从回收站恢复时，不让路径变长的（改短、恢复到原来的地方）一定能做，变长的不能超过 227（在资源管理器里建得很深、原来就放不下新待办的文件夹不因为要留的长度而不让动）；新建待办只要文件路径不超过 259。图片（`.assets\{待办 id}\{文件名}`）也不超过 227：放不下原来的名字时截短，一个字都放不下时不插入；移动、改名、恢复时图片和别的文件一样算（`.assets` 里的文件夹不是项目，不用给待办文件名留地方），项目文件夹不为以后的图片多留地方。超过了就不做、提示路径太长
- 正文按 UTF-8 保存；放进来的 GBK（ANSI）或带 BOM 的 UTF-16 文件也能正常显示，在软件里改过后转存为 UTF-8；认不出编码的文件只读显示，需要修改时用默认程序打开
- `.todos.json` 损坏时会备份为 `.todos.json.broken-时间戳` 并重建，正文不受影响
- 运行期间监听整个数据目录：在外部（网盘同步、别的程序、资源管理器）增删改名了工作区、项目（各级子项目）的文件夹、`.md`、`.todos.json` 或 `.projects.json` 时自动刷新；`.` 开头的（`.state.json`、设置文件、保存时的临时文件 `.名字.tmp`、图片的附件目录 `.assets` 等，`.recycle` 只刷新开着的回收站）、直接放在数据目录和工作区文件夹里的文件（如设置备份的 zip）、项目里不是 `.md` 的文件不算。数据目录在不支持变化通知的网络盘上时，只在切回窗口、按 F5 时刷新
- 删除的工作区 / 项目 / 待办先进软件的回收站（`.recycle`），可以撤销、恢复；在回收站里彻底删除、清空或放满 30 天的连同说明进入 Windows 回收站（名字是标题加 id，名字太长、里面的路径会超过 259 个字符时标题截短或只用 id；从 Windows 回收站还原后回到 `.recycle`，又能在软件里恢复；Windows 回收站不可用时移到数据目录下的 `.trash`）；里面的路径只用 id 也超过 259 的（在资源管理器里建得很深的）Windows 回收站放不下，不移，留在软件的回收站里并提示
- 待办数据的备份包（`TodoList-data-*.zip`）里是数据目录里各工作区文件夹里的全部，多深都算（各级项目、子项目的文件夹，待办正文，各级的 `.todos.json` 和项目的顺序 `.projects.json`，各级项目里的附件目录 `.assets` 等，保存时的临时文件 `.名字.tmp` 除外）和 `.state.json`；不含 `.recycle`、`.trash`、设置文件、WebDAV 设置和数据目录里的别的文件。`backup.json` 记着类型（`data`，设置备份里的是 `settings`）、软件版本、备份时间、工作区数和待办数（各级子项目里的都算）、数据的指纹（各文件的路径、大小、修改时间和各文件夹的路径，`.state.json` 除外、各级的 `.projects.json` 和图片也算，自动备份据此判断数据变没变）和各文件、文件夹的修改时间（恢复时改回去）。可以直接用资源管理器打开看
- 恢复数据时先解压到数据目录里的 `.restoring-…`（`.` 开头，监听时不算）、检查过路径（`..`、绝对路径、盘符等都不行；恢复到这里的数据目录后会超过 259 个字符的，如数据目录比备份时的长，整个不恢复），拿着存储层的锁把现在的数据打包成 `…-恢复前.zip`，再把工作区和 `.state.json` 换成备份里的（只是改名，很快；记成软件自己写的，监听时不算外部改动）；中途失败时换回原来的。改名之前先在 `.restoring-…` 里写下记录 `journal.json`（现在的、备份里的各是哪些，恢复前的数据备份在哪里；写临时文件、落盘后再换上），程序在替换中途退出时，下次启动时先凭它换回原来的数据，已经换完的做完收尾，处理不了的原样留着，结果提示一次
- WebDAV 密码保存在 Windows 凭据管理器（普通凭据 `webdav.com.whr.todolist`），不写进任何文件，也不会进入备份包
- 访问 WebDAV 时使用 Windows 的代理设置（或环境变量 `HTTPS_PROXY`），代理例外和 `NO_PROXY` 里的地址直连

界面状态里和数据有关的记在数据目录的 `.state.json`，跟着数据走（换电脑、重装系统后还在；数据目录用网盘同步时一起同步，几台电脑同时开着时以最后写的为准）：侧栏选中的工作区，各工作区上次打开的待办，上次停在哪里（开屏「回到上次的位置」用），右侧打开着的标签（顺序、哪个是预览标签；分屏时两边各自的，和分屏的方向、比例、各自正显示着的、哪一边有焦点），各待办的编辑位置和编辑模式（各最多记 300 条，最久没动过的先忘掉；编辑模式只记切换过、和默认不一样的）。改动后 5 秒内写盘，隐藏到托盘、退出前立即写；以前的版本记在 localStorage 里的，第一次启动时搬过来。

其他界面偏好只记在本机（WebView2 的 localStorage）：侧栏宽度，各工作区的折叠状态、排序和隐藏已完成（已完成的待办、全部完成的项目；还没单独设置过的工作区沿用以前不分工作区时的设置），是否显示大纲，完成记录的时间范围，上次导出到的目录。导出的文件存在导出时选的地方，不在数据目录里。各待办的撤销记录（最多 50 条）、分屏时两边各自的编辑位置和后退 / 前进的记录（最多 100 处）只在这次运行期间记在内存里。

测试时可用环境变量 `TODOLIST_DATA_DIR` 指定其他数据目录；自动备份默认的目录跟着变成它旁边的「目录名-backups」（如 `%TEMP%\todolist-test-backups`），不会写进真实的 `TodoList-backups`。

## 开发

需要 Node.js、Rust（MSVC 工具链）和 WebView2（Windows 11 自带）。

在 Linux 上开发（Tauri 在 Linux 上编不了）时怎么验证、怎么交到 Windows 上测，见 [docs/linux-windows-workflow.md](docs/linux-windows-workflow.md)。

```bash
npm install
npm run tauri dev       # 开发调试
npm run build:debug     # 不打安装包的 debug 版 exe，见下文「本机测试用的构建」
npm run build:fast      # 不打安装包、不做 LTO 的优化版 exe，见下文
npm run tauri build     # 正式打包，安装包在 src-tauri/target/release/bundle/nsis/
npm run release         # 打包并安装到本机，见下文
npm run release:fast    # 同上，但用 release-fast profile 构建，快很多
npm run lint            # ESLint 检查前端代码（含 React hooks 的规则），要零错误、零警告
npm test                # 前端单元测试（vitest：标签的规则、联想和颜色、搜索匹配（含 #标签名）、排序（含按优先级）、项目的顺序（按名称 / 手动排序，多级的每一层各排各的；拖到项目的上沿 / 下沿算放在哪里、能不能放，放下后那一层的顺序）、按标签和优先级筛选（筛掉哪些项目）、编辑快捷键、列表缩进、列表的排版、代码块、查找、编辑位置、标签页和分屏、两个编辑器同步正文、后退 / 前进、快捷键检查、完成记录的分组、日期、范围和查找、导出的项目树和顺序（多级的每一层）、外部修改冲突和离开待办时存不上的另存（含分屏两边开着同一条待办）、退出前写盘、恢复待办数据的流程（分屏两边打开着的待办先存盘、存不上不恢复，之后不再写界面状态）、数据目录在外部变了时刷新什么、图片的地址和插入、撤销记录接到改了链接的正文上、表格的内容和哪些表格渲染等）
cd src-tauri && cargo test   # 单元测试（存储（含图片的附件目录和它的路径长度、标签和优先级、项目的顺序（多级的每一层））、监听数据目录、设置备份、待办数据的备份与恢复（多级子项目、各级的 `.projects.json` 和附件目录）、WebDAV（本机起一个假的服务器）、开机自启的注册表读写、自动更新的标记（只提示一次、删不掉时不算刚更新过）和定时检查的间隔（电脑睡眠的时间也算）、导出（Markdown 渲染、安全处理、图片嵌入（含深层项目的，粘贴、拖进来存在 `.assets` 里的，地址照编辑器的写法，移到别的项目（跨层级）换了 id 后的）、元信息里的标签和优先级、文件名、文档的结构：多级的章、标题的级别、目录和顺序））
npm run e2e             # Windows 上的端到端测试：启动测试版程序，模拟按键、鼠标，检查界面、文件、注册表、窗口，见下文
```

前端单元测试放在被测模块旁边（`*.test.ts`），配置在 `vitest.config.ts`。默认在 Node 里跑：编辑命令直接构造 CodeMirror 的 `EditorState` 测（`src/editor/testState.ts` 提供用 `|`、`«»` 标出光标和选区的写法，和编辑器用同一份 Markdown 解析），不需要 DOM；要用 DOM、`localStorage` 的（`workspaceState.test.ts`，渲染 `SettingsProvider` 的 `settings.test.ts`，在 antd 的 `App` 里挂上 `useUpdatePrompt`、看右下角的提示和确认框的 `update.test.ts`；happy-dom 里 antd 的动画不会结束，关掉的提示、对话框留在页面里）在文件开头指定 happy-dom。用例按 docs/requirements.md 里写的行为写，不照着实现抄期望值。

ESLint 的配置在 `eslint.config.js`：typescript-eslint 的推荐规则，加上 eslint-plugin-react-hooks 的全部推荐规则（`rules-of-hooks`、`exhaustive-deps` 和 React Compiler 的 `refs`、`immutability`、`purity`、`set-state-in-effect` 等）。代码里有不少刻意绕开 hook 依赖的写法（用 ref 拿最新的值、只在挂载时执行一次的 effect），这些地方就地加了 `eslint-disable-next-line` 并写明原因；不要为了消掉警告机械地补依赖，那会让只该执行一次的 effect 反复执行。

有 CI（`.github/workflows/ci.yml`）：每次 push、提 PR 时在 GitHub 的 Windows 机器（windows-latest，Node 24、stable Rust，缓存 npm 和 Rust 的依赖）上依次跑 `npm ci`、`npm run lint`、`npm test`、`npm run build`、`cd src-tauri && cargo test`；提交前在本机按同样的顺序跑一遍即可。`npm run build` 放在 `cargo test` 前面：`tauri::generate_context!` 在不是 dev 的构建（`tauri build`）里要把 `frontendDist`（`../dist`）嵌进程序，现在的 `cargo test` 是 dev 构建、用 `devUrl`，其实不读 `dist`，先构建好是为了以后换了构建方式也不出错。端到端测试是另一个 workflow（`.github/workflows/e2e.yml`），见下文「端到端测试（Windows）」。

测量扫描数据目录的耗时（`list_workspaces`、`load_workspace`，含预览缓存是空的和已缓存两种情况）：用一份测试数据（不要用真实数据），跑标了 `#[ignore]` 的 `bench_scan`。它只读不写（数据和 `.todos.json` 一致时扫描不会写盘）：

```powershell
cd src-tauri; $env:TODOLIST_BENCH_DIR="$env:TEMP\todolist-bench"; cargo test --profile release-fast --lib bench_scan -- --ignored --nocapture
```

怎么跑的：

- 构建测试版（`src-tauri/target/e2e/debug/todo-list.exe`，identifier `com.whr.todolist.e2e`、产品名「待办清单自动测试」）：和安装版、手动测试的构建是不同的应用，可以同时运行，开机启动项、窗口位置、WebView2 缓存都分开。全局快捷键用 Ctrl+Alt+Y（显示 / 隐藏主窗口）、Ctrl+Alt+J（快速记录），避开安装版的 Ctrl+Alt+T、Ctrl+Alt+N；被占着时开头会提示
- 前端从 Vite 开发服务器（:1420）加载：已经有一个在跑就用它（要是这个工作副本的），否则自己启动、跑完关掉
- 每个套件开始前退出测试版、重建测试数据（`%TEMP%\todolist-e2e\data`，`e2e/lib/fixtures.mjs`）、清掉自动备份（`%TEMP%\todolist-e2e\data-backups`），再启动；不碰真实数据和真实的备份目录。测试数据的设置里自动备份是关着的（开着的话每个套件启动几秒后都打包一份，打包时开着文件，和套件在外面改名、删除文件夹撞上时偶尔失败），只有 `backup` 套件用默认的（开着）；自动检查更新同样关着（启动后不去连更新服务器），只有 `update` 套件打开，它连的是自己起的假服务器（`127.0.0.1:9231`，测试版的配置里换了更新地址和公钥，见 `e2e/lib/app.mjs` 的 `testConfig`）；数据目录的监听照常开着，套件在外面改的文件几秒内刷新出来，等界面跟着变时用 `t.until`。`history` 离半夜 12 点不到 5 分钟时先等过了半夜再跑（「今天」「昨天」在中途换了的话分组对不上）
- 测试版的主窗口在配置里打开 WebView2 的远程调试端口 9223（构建时经 `TAURI_CONFIG` 给它加上 `additionalBrowserArgs`；不用环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，有的机器上 WebView2 不认它）。设了这一项就不带 wry 默认的参数，要一起写上；快速记录小窗沿用主窗口的参数，同一个 WebView2 数据目录里参数不一致时窗口建不起来。经这个端口（`e2e/lib/cdp.mjs`）在页面里执行代码、发送真实的键盘 / 鼠标事件；窗口状态、注册表、回收站、任务栏经 PowerShell 调 Win32 API（`e2e/win/win.ps1`，带 UTF-8 BOM）。全局快捷键是直接给测试版的热键窗口发 `WM_HOTKEY`，不模拟真实按键，按键不会跑到别的程序里
- 跑完删掉测试版的开机启动项；彻底删除、清空回收站、放满 30 天的检查会真的移到 Windows 回收站，跑完从那里还原回测试数据目录再一起删掉，不在你的回收站里留东西

注意：

- 跑的时候会弹出测试版的窗口（主窗口会最大化一下），抢前台；别在跑的时候打字。模拟的快捷键不是真的按键，测试版要拿到前台只能靠 tao 的 `set_focus`（模拟按一下 Alt 再 `SetForegroundWindow`）：锁屏了、前台的程序以管理员身份运行（模拟按键送不进去）、或有人正在别的程序里操作时，Windows 不让换前台。`quick`、`regress` 开头试一下，拿不到时「在前台」一类的检查记为跳过并说明原因，不算失败；解锁、换个普通程序在前台、别动键盘鼠标后重跑那个套件即可。别的程序（如会议软件）过一两秒就抢走前台时，快速记录小窗会按设计藏起来，后面的检查可能失败，同样重跑。拖动中窗口失去焦点、或真的鼠标在测试版窗口上动了，页面会按设计取消拖动：`drag` 看到了就松开重拖（打出「↻ 拖动被打断」），最多三次
- `desktops` 套件只能用真的按键（Ctrl+Win+D / ← / → / F4）新建、切换、关掉虚拟桌面，会动到整个桌面：本机已经开着好几个虚拟桌面时跳过不跑，跑完关掉它新建的那个
- 新套件放在 `e2e/suites/`，默认导出 `async function (t)`：`t.main` 是主窗口的页面（`ev` 执行页面代码，`press`（`press(按键, { repeat: 5 })` 是按住不放）、`type`、`click`、`drag` 等），`t.quick()` 是快速记录小窗，`t.win` 是窗口、快捷键、注册表、回收站的操作，`t.check(名称, 是否通过, 附加信息)` 记一项检查，`t.until(条件)` 等到条件成立（每 200 毫秒看一次，最多 5 秒；等页面、文件的变化时用它，别用固定时长的 `sleep`，机器慢时不够），`t.restart()` 重新启动；测试版中途退出、崩溃，页面断开以后，`ev`、`press`、`click` 等都抛错（只有 `send` 不抛），套件记为出错中断，套件跑完、`t.restart()` / `t.quit()` 时页面已经断开了的也当作测试版自己退出（崩溃）了、算没通过，故意让它退出的（如 `update` 套件点「立即更新」）退出后先把 `t.main` 设成 null 再 `t.restart()`；要在测试数据默认的设置（`fixtures.mjs`）上改几项时导出 `settings`（如 `backup` 的 `{ autoBackup: undefined }`，用软件的默认值）；再加到 `e2e/run.mjs` 的 `SUITES`。页面里能用的工具函数（`row`、`view`、`openTodo`、`menuItem`、`button` 等）在 `e2e/lib/page.mjs`
- 测不到、要手动试的（真的注销 / 重启后的开机自启、安装包的卸载和升级、多显示器、托盘菜单、真实的输入法）列在 `docs/windows-test-checklist.md`

#### 在 GitHub Actions 上跑

`.github/workflows/e2e.yml`：每次 push 时在 windows-latest 上 `npm ci` 后跑全部套件，加上构建测试版约 9 分钟（Rust 的编译缓存放在 `src-tauri/target/e2e`）。也可以手动跑，只跑其中几个套件：在 Actions 页面点「Run workflow」，或

```bash
gh workflow run e2e.yml --ref <分支> -f suites="batch recycle"
gh run list --workflow E2E --limit 3     # 找到这次的编号
gh run view <编号> --log                 # 看结果；没通过时 gh run download <编号> -n desktop 下载当时整个桌面的截图
```

那台机器是 Windows Server、1024×768 的交互式桌面，以管理员身份运行、没人操作，「在前台」一类的检查都能做。和本机不同、测试里已经处理了的几处：

- WebView2 不认环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`（浏览器进程的命令行里只有 wry 自己的参数），所以远程调试端口写在测试版的配置里（见上文「怎么跑的」）
- `TEMP` 是短文件名（`C:\Users\RUNNER~1\...`），Windows 回收站记的原位置却是长路径：测试数据目录用 `realpathSync.native` 换成长路径
- 机器比较慢：等页面、文件变化的检查用 `t.until(条件)`，别用固定时长的 `sleep`

### 本机测试用的构建

`npm run tauri build` 慢在三处：release 配置开了 `lto = true`、`codegen-units = 1`（最耗时），前端要重新 `tsc && vite build`，最后还要打 NSIS 安装包。测试时按需要跳过：

| 命令 | 产物 | 适用 |
| --- | --- | --- |
| `npm run tauri dev` | 不产出独立 exe，连 Vite 开发服务器（:1420） | 日常改功能：前端改动热更新，不用重新编译；Rust 增量编译 |
| `npm run build:debug` | `src-tauri/target/debug/todo-list.exe` | 要一个能直接双击运行的 exe（前端已打包进去，不需要 Vite）；未优化，性能与正式版不同 |
| `npm run build:fast` | `src-tauri/target/release-fast/todo-list.exe` | 接近正式版的性能：用 `Cargo.toml` 里的 `release-fast` profile，优化级别同 release，但不做 LTO、16 个代码单元并行、增量编译 |
| `cd src-tauri && cargo test` | — | 只改了存储、备份、WebDAV 等 Rust 逻辑，不用启动界面 |
| `npm run release:fast` | 安装包，装到本机 | 频繁装到本机试用，见下文「安装到本机与升级」 |
| `npm run tauri build` / `npm run release` | 安装包 | 发布前完整跑一次 |

参考耗时（本机）：`build:fast` 首次约 2 分钟，之后只改 Rust 代码时几秒到十几秒；`build:debug` 约 30 秒。三种构建的目录（`debug`、`release-fast`、`release`）互不覆盖。

测试构建的注意事项：

- 这些 exe 和安装版是同一个应用（identifier `com.whr.todolist`），单实例插件会把新启动的那个交给已在运行的安装版（把它的窗口调到前台），新启动的自己悄悄退出。要么先从托盘「退出」安装版，要么构建时换一个测试用的 identifier，两者就能同时运行：

  ```powershell
  $env:TAURI_CONFIG='{"identifier":"com.whr.todolist.test"}'; npm run build:debug
  ```

  换了 identifier 的构建在 WebView2 缓存（localStorage 里的侧栏宽度、折叠状态、排序）和凭据管理器里的 WebDAV 密码（`webdav.com.whr.todolist.test`）上与安装版分开，上次的位置、编辑位置和编辑模式在数据目录的 `.state.json` 里，要靠下面的 `TODOLIST_DATA_DIR` 分开；全局快捷键仍然会和安装版冲突，测试版里可以改成别的（如 Ctrl+Alt+Y）。开机自启的启动项名是产品名，测试版里打开、关闭开机自启会改到安装版的启动项；要分开就同时换一个产品名（`$env:TAURI_CONFIG='{"identifier":"com.whr.todolist.test","productName":"待办清单测试"}'`）
- 运行测试构建时用 `TODOLIST_DATA_DIR` 指向临时目录，不要动真实数据：

  ```powershell
  $env:TODOLIST_DATA_DIR="$env:TEMP\todolist-test"; .\src-tauri\target\release-fast\todo-list.exe
  ```

  设置文件也在这个目录里，自动备份默认存在它旁边的 `%TEMP%\todolist-test-backups`。删除的东西先进这个目录里的 `.recycle`，在软件的回收站里彻底删除、清空时仍然进系统回收站
- 调试构建（`npm run build:debug`、`npm run tauri dev`）设了环境变量 `TODOLIST_PDF_PRINT_DIALOG`（随便什么值）时，导出 PDF 不直接存成 PDF，总是退回系统的打印对话框，用来手动试退回的流程（WebView2 是新的，平时走不到）；正式版不认这个变量

代码结构：

- `src-tauri/src/store.rs`：文件存储（项目文件夹里的各级子文件夹都是子项目，扫描时用栈不用递归）、元数据对齐、名称校验（`is_reserved_name`：Windows 的保留名称，含上标数字的 COM¹～COM³、LPT¹～LPT³ 和 CONIN$、CONOUT$，新建、改名、拖进来的图片、导出的默认文件名和恢复数据时检查备份里的路径都用它）、完整路径长度检查（`PATH_LIMIT` = Windows 的 `MAX_PATH_CHARS` 减去回收站要留的 `RECYCLE_ROOM`；新建项目用 `check_new_folder`，移动、改名、恢复用 `check_grow`：路径不变长不检查，变长时看里面每个文件、文件夹（包括图片；`.` 开头的文件夹和它里面的文件夹不是项目，不用给待办的文件名留地方）），软件的回收站（删除时连同说明移进 `.recycle`，恢复、彻底删除、清空、放满 30 天的移到系统回收站，移之前算好里面最长的路径（`purge_dir`）：改成看得懂的名字后超过 259 时标题截短，只用 id 也超过的不交给系统回收站、留在 `.recycle`；单元测试里「系统回收站」是 `.trash`，不碰用户真正的回收站），界面状态文件 `.state.json` 的读写（内容由前端决定），恢复待办数据时拿着锁把数据目录里的工作区和 `.state.json` 换成备份里的（`replace_data`，中途失败换回原来的，改名都记成软件自己写的；改名之前在临时文件夹里写下记录 `journal.json`：两份名单和恢复前的数据备份。换的时候每一项只在一处——现在的在数据目录或 `old`、备份里的在 `new` 或数据目录，改名不覆盖已有的——所以凭名单和磁盘上现在的样子就知道换到了哪里，`recover_restore` 在启动时据此换回或收尾，说不清的原样留着；没换回来就交还给用户之后（替换失败没能全部换回、启动时没能处理），临时文件夹里放一个标记 `exposed`：之后再换回时 `new` 里的可能在软件里改过，整个改名成 `new-换回前用过` 留着不删（改不了名就什么都不删），界面这期间又写的 `.state.json` 让给原来的那份；收拾临时文件夹时先删记录再删别的，收尾到一半退出也能接着收尾；改名遇到拒绝访问、共享冲突时稍等再试几次），项目的顺序（每一层的 `.projects.json`，层数不限：`load_workspace`、`list_projects` 给出各项目在它那一层里排第几和工作区是不是手动排序，按名字排要用中文的拼音顺序，在前端排；`reorder_projects`、`set_projects_manual`，改名、移动、删除、恢复项目时跟着改）；左侧显示的正文开头（预览）缓存在内存里，按 .md 的修改时间和大小判断是否失效，文件没变就不重新读（窗口每次获得焦点都要重新加载选中的工作区，待办多时读几千个文件开头很慢），缓存是空的时（刚启动）分给几个线程一起读；完成记录（`list_done`）同样扫描各级项目的元数据，只给列出的已完成待办读正文开头（`scan_project_for`）；全文搜索（`search`）用的正文全文同样缓存在内存里，按同样的办法判断是否失效，软件里保存时直接丢掉那一条（连着很快保存两次、长度又一样时修改时间和大小可能都没变）；缓存不写进任何文件，免得数据目录用网盘同步时多出冲突；每次写完记下写过的文件、文件夹现在的样子（`OwnWrites`，所有写入都经 `atomic_write`、`create_child_dir`、`rename_dir`、`create_dirs` 或就地 `note_own`），监听数据目录时据此认出软件自己写的（见 `watch.rs`）；`note_own` 同时给数据目录记一次变化（`note_change`，数据目录里 `.` 开头的不算；监听到的外部改动也记），自动备份据此判断要不要重扫数据目录（`change_count`）；正文里的图片（附件目录 `.assets/{待办 id}/`）的存放（`save_image` 粘贴的、`import_image` 拖进来的，名字按路径长度截短：`fitting_names`）、找文件（`image_file`），移动、删除、恢复待办时附件目录跟着走（路径变长时 `check_assets_grow` 检查里面的图片），换了 id 时改正文里的链接（`relink_assets`：只改地址开头的 `.assets/{旧 id}/`，修改时间留着原来的），另存为新待办时复制一份（`create_todo_from`，放不下时不复制）
- `src-tauri/src/watch.rs`：监听数据目录（notify，递归监听，`TODOLIST_DATA_DIR` 指定了别的数据目录时监听它）。一阵变化合起来算一次（静下来 0.3 秒，一直在变时最多攒 2 秒；一批里 200 处以上当成全部变了），按路径算哪些变化算（`classify`：工作区、项目、各级子项目的文件夹（层数不限，同 `store.rs` 的扫描），待办的 `.md` 和 `.todos.json`，工作区、各级父项目里的 `.projects.json`；`.` 开头的（连同 `.` 开头的文件夹里的，含恢复待办数据时的临时文件夹 `.restoring-…`）、不是 `.md` 的文件（含导出到数据目录里的 HTML / PDF）、文件夹自己的修改时间都不算，`.recycle` 单独报），再去掉软件自己写的：`store.rs` 每次写完记下写过的文件、文件夹现在的样子（`OwnWrites`：文件的修改时间和大小、在不在，只认 10 秒内的；文件夹新建、改名、删掉时，里面之前记下的按现在的样子重新记），监听到的变化和记下的一样就是自己写的。收到的每个变化（只是读了一下的不算；软件自己写的、不刷新界面的附件目录里的图片也算）还给数据目录记一次变化（`count_change` → `store.rs` 的 `note_change`），出错、要重新扫描的、不带路径的当成整个变了（notify 在 Windows 上缓冲区满了时悄悄停掉、什么都不报，那种靠自动备份隔 6 小时的重扫兜底），自动备份据此判断要不要重扫。有要报的在监听线程里交给 `lib.rs`；没有变化时线程一直等着系统通知
- `src-tauri/src/settings.rs`：应用设置（快捷键、改过的编辑快捷键、主题、字号、编辑区背景色、保存方式、开屏方式、开机自启时是否显示主窗口、快速记录存到哪个项目、自动备份的开关、目录、份数、是否上传 WebDAV、是否自动检查更新）的读写和字号、保存间隔、自动备份份数的范围；后加的快捷键（快速记录、左右 / 上下分屏）和以前的设置文件里已经用了同一组按键的让给原有的、设为不使用
- `src-tauri/src/autostart.rs`：开机自启，读写注册表的 `Run`（启动项名是产品名，Tauri 的卸载程序不是升级时会删掉它）和任务管理器的禁用标记 `StartupApproved\Run`；开机自启时命令行带 `--autostart`，主窗口一开始是隐藏的（`tauri.conf.json` 里 `visible: false`），`lib.rs` 的 `setup` 里按设置决定显不显示。只在托盘里时先不恢复「最大化」（恢复最大化会把窗口显示出来），第一次显示主窗口时再恢复；一直没显示过就退出时，记住窗口状态的插件会按隐藏着的窗口记成没最大化，退出时（`RunEvent::Exit`，插件之后）把主窗口那一项改回启动时的样子
- `src-tauri/src/backup.rs`：设置备份包的打包、解包、命名和读本地的备份文件；两种备份包共用的说明文件 `backup.json`（据此认出拿错了的备份）、数据备份的文件名，WebDAV 上的备份列表（两种都列，标明是哪种）
- `src-tauri/src/data_backup.rs`：待办数据的备份与恢复。打包时列目录、读每个文件都拿一下存储层的锁（`Store::locked`，免得和保存、改名同时进行；Windows 上文件夹里有文件开着时这个文件夹改不了名），读的时候文件没了说明数据在变，从头再来；先写成 `.名字.tmp`，写完再改名。恢复时检查路径（不安全的，和恢复到数据目录后会超过 `MAX_PATH_CHARS` 的，解压之前就整个不恢复；解压到 `.restoring-…` 时路径更长、可以超过 260，靠 std 在 Windows 上自动换成 `\\?\` 开头的长路径）、解压到 `.restoring-…`、改回修改时间，再交给 `Store::replace_data` 拿着锁先备份现在的、再换；替换失败、没能全部换回来时（记录还在）`clean_staging` 只删下载的备份，别的留给下次启动。还有没处理完的（别的 `.restoring-…` 里有记录）时不再恢复。启动时 `recover_leftovers` 找出数据目录里的 `.restoring-…`（后恢复的先处理）交给 `Store::recover_restore`（换完了要删掉换下来的原来的数据时，先看恢复前的数据备份里是不是正是这些：`backup_holds` 比说明里记的指纹和 `old` 的指纹），结果记在 `BackupJobs` 里等前端取走（`take_restore_recovery`，只给一次）。自动备份的判断（满 24 小时、指纹变了；扫过一遍、数据和最新的一份一样之后，`AutoScan` 记着那时数据目录变了几次（`store::change_count`）和最新的一份是哪个文件，都没变、离上次扫不到 6 小时（没在监听数据目录时 1 小时）就不再扫）、只留最近几份（本地和 WebDAV），默认的备份目录和检查（不能在数据目录里面），这次运行期间的结果和「同时只做一件」（`BackupJobs`）；单元测试用 `webdav.rs` 里本机起的假 WebDAV 服务器
- `src-tauri/src/export.rs`：导出成 HTML（导出 PDF 时 `lib.rs` 的 `print_pdf` 把同样的 HTML 打印出来）。前端给出导出哪些待办、什么顺序：按侧栏的顺序排好的项目树（每个项目带着自己排好序的待办和排好序的下一级子项目，层数不限；Rust 端不再排），这里按顺序从磁盘读出来（`collect`），渲染成一个文件（`render`：封面、目录、按项目的层级递归分章，`blocks` 按顺序列出章的开始和结束、待办，正文和目录都按它走、锚点对得上；样式写在里面，总是浅色、打印时每条待办、每章分页，紧跟在章的标题后面的第一条待办、下一级的章不分页；每节的元信息里有优先级和标签，标签的颜色用 `tag_color`，和前端 `tags.ts` 的 `tagColor` 同一个算法，两边的单元测试用同一组例子）；正文用 pulldown-cmark 按 GFM 渲染，网址、邮箱照编辑器（lezer）的规则变成链接，脚注挪到每一节末尾；渲染结果连同正文里写的 HTML 交给 ammonia 做安全处理；本地图片（相对于 .md 所在文件夹、绝对路径、file:///）读进来嵌成 base64 的 data URI，按文件头定类型；默认文件名（`project_base`：项目的各级用「 - 」连起来、太长时中间折叠，`file_name`：去掉不能用的字符、截短、避开保留名称）；导出 PDF 用的窗口里和 Tauri 无关的算法也放在这里（测试壳里测得到）：退回打印对话框时窗口的大小（`print_window_size`）、临时文件的名字和启动时哪些算丢下的（`temp_html_name`、`temp_html_pid`、`abandoned_temp_html`：这次运行中在用的不删，进程号和这个进程一样的、写它的进程不在了的、超过一天的删；软件是单实例的，但换了 identifier 的测试版能同时开着，别的实例的不到一天时留着）、窗口要去别的地址时怎么办（`print_navigation`：去掉锚点、还原转义、不分大小写后还是导出的这一页才去；网页、邮件链接交出去，`is_web_link` 也在这里，`open_url` 命令用它；别的不理）
- `src-tauri/src/update.rs`：自动更新里和 Tauri 无关的部分：运行安装程序之前在这台电脑的配置目录（`%APPDATA%\com.whr.todolist`，和记住窗口位置的文件在一起）记下从哪个版本更新到哪个版本（`update-pending.json`），下次启动时读出并删掉（`take_outcome`：现在的版本就是要更新到的版本时算装好了；删不掉时不算刚更新过，标记留着、以后哪次删掉了再看，那时的版本既不是更新前的也不是要更新到的就不提示）；定时检查更新这次等多久（`check_wait`：离上次检查过了 6 小时就马上检查，否则最多等 10 分钟就醒来再看）
- `src-tauri/src/webdav.rs`：WebDAV 连接配置、密码存取、客户端（含代理处理；数据备份下载时边收边写进文件，上传、下载的超时放宽到 30 分钟）
- `src-tauri/src/lib.rs`：Tauri 命令、打开外部程序和链接、系统托盘、全局快捷键（显示 / 隐藏主窗口和快速记录两个，按下时按 `GLOBAL_KEYS` 找是哪个）、快速记录小窗（label `quick`，第一次用时建，启动 3 秒后也先建好；之后藏起来留着；`skip_taskbar` 只去掉任务栏按钮，每次显示后再标成工具窗口（`WS_EX_TOOLWINDOW`），Alt+Tab 里也没有；WebView2 的参数（`additionalBrowserArgs`）沿用主窗口配置里的；存好后给主窗口发 `data-changed`、`open-todo` 事件）、监听数据目录（`setup` 里 `watch::start`，建不起来时只在标准错误输出里记一行；监听到的变化经 `data-changed` 发给主窗口，带上变了什么（`DataChanged`：`all`、`paths`、`recycle`），主窗口藏在托盘里时攒着、`show_main_window` 时一起发）、主窗口在别的虚拟桌面上时调出前先挪到当前桌面（`move_to_current_desktop`：在后台线程里经 `IVirtualDesktopManager` 问它在不在当前桌面，不在时 `MoveWindowToDesktop` 挪到当前桌面，当前桌面的 id 读 explorer 记在注册表里的（`current_desktop_ids`，Windows 10、11 记在不同的地方）；读不到、挪不过去时退回直接 `ShowWindow` 藏起来、等 explorer 把它从原来的桌面上拿掉、再显示出来，不经 tao 的 hide / show，它隐藏最大化的窗口前会先 `SW_MAXIMIZE` 激活它）、窗口图标、本地备份、恢复、导出时的文件对话框（tauri-plugin-dialog，只在 Rust 端调用，前端没有对话框的权限；设置的从数据目录打开，待办数据的从自动备份目录打开，导出的从上次导出到的目录或「文档」打开）、`setup`   - `tables.ts`：实时渲染时的表格：按语法树拆出表头、对齐、各格的内容（`tableModel`）和单击格子时光标放在哪里，光标（选区）不在表格里时整个表格换成 `<table>`（外层横着滚动，`contain: inline-size` 不让很宽的表格把编辑区撑宽）。替换的是好几行（块级），CodeMirror 只许从 StateField 里给，编辑器有没有焦点、鼠标是不是按着由事件告诉这个字段（每个编辑器各自的，分屏时两边不互相影响）

  - `codeFences.ts`：代码块自动补结尾、Ctrl+Enter / ↓ 跳出代码块
  - `outline.ts`：大纲。按语法树找出标题、去掉标记（`outlineItems`），报告正在看的位置（光标在可见区域里时是光标处，否则是可见区域顶部，`trackReadingPos`），跳到标题；大纲面板是 `components/Outline.tsx`，`TodoEditor` 在打字停下片刻后（和字数一起）更新它，正在看的标题变了才重新渲染

```bash
npm run release              # 用当前版本号打包并安装
npm run release -- patch     # 先升版本号（0.1.0 → 0.1.1）再打包安装；也可以是 minor、major 或 0.2.0 这样的具体版本
npm run release:fast         # 同 release，但用 release-fast profile 构建（不做 LTO），参数用法一样
```

`release:fast` 编出来的程序性能接近正式版、体积稍大，适合频繁装到本机试用；安装包在 `src-tauri/target/release-fast/bundle/nsis/`。

`scripts/release.mjs` 依次：

1. 带了版本参数时，改 `package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 里的版本号（`Cargo.lock` 在构建时自动更新），这几个文件的改动要一起提交
2. `npm run tauri build`（`release:fast` 用 `npm run tauri -- build -- --profile release-fast`）
3. 如果程序正在运行，提示从托盘「退出」并等它退出后再继续。安装程序会直接结束所有名为 `todo-list.exe` 的进程，先正常退出才能保证正在编辑的内容已保存
4. 运行安装包（只显示进度条，不用点下一步），装完自动启动。已经装过时按升级处理：直接覆盖，不先卸载旧版，也不会重建你删掉的快捷方式

程序只装给当前用户，位置是 `%LOCALAPPDATA%\待办清单\`，不需要管理员权限，可以在「设置 → 应用」里卸载。待办数据在 `%USERPROFILE%\TodoList`，安装、升级、卸载都不会动它。

平时请从开始菜单或桌面快捷方式启动安装版，不要直接运行 `src-tauri\target\release\todo-list.exe`：两者是同一个应用，同时只能开一个；而且它运行时文件被占用，再次构建会报拒绝访问（os error 5）。

### 发布到 GitHub

`.github/workflows/release.yml`：推送 tag 时在 GitHub 的 Windows 机器（windows-latest）上 `npm ci` 后 `npm run tauri build`（和 `npm run release` 一样是 release profile，不用编译缓存），发布成这个 tag 的 Release（标题是 tag，附件是安装包和 `latest.json`）。安装包原名「待办清单_<版本>_x64-setup.exe」，GitHub 会把附件名里的中文换掉，所以改名成 `TodoList_<版本>_x64-setup.exe` 再上传。

```bash
npm run release -- 0.2.0          # 改版本号（同时在本机打包、装上试一下），见上文「安装到本机与升级」
git commit -am "chore: 版本号改为 0.2.0"
git tag v0.2.0
git push origin main v0.2.0
gh run list --workflow Release --limit 3
```

自动更新（见 `lib.rs` 的「自动更新」）靠这里发布的东西：

- 签名：打包时打开 `createUpdaterArtifacts`（只在这个 workflow 里经 `--config` 打开，本机打包不用私钥），tauri 用私钥给安装包签名（`.sig`）；软件里只认 `tauri.conf.json` 里 `plugins.updater.pubkey` 那个公钥，签名对不上的不安装。私钥和密码放在仓库的 Secrets 里（`TAURI_SIGNING_PRIVATE_KEY`、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD`），生成时的原件在维护者电脑的 `~/.tauri/todolist-updater.key`（密码在旁边的 `.password`），要另外备份好：私钥丢了以后发的版本签不了名，已经装了的软件就再也收不到自动更新，只能让用户手动装一次换了公钥的新版
- `latest.json`：版本号、更新说明、安装包的签名和下载地址（这个 release 的附件）。软件检查的是 `releases/latest/download/latest.json`，即标成 Latest 的那个 release 里的；下面的 latest 任务把版本号最大的标成 Latest，补发旧版本不会让已装的软件「更新」回去
- 更新说明：和上一个 tag 之间 `feat` / `fix` / `perf` 的提交说明（去掉前缀；scope 是 `e2e`、`ci`、`test`、`docs`、`build` 的不算），没有时写「其他改进」；release 的说明和软件里的更新提示都用它，所以提交说明要写成用户看得懂的
- 0.1.1 及以前发布的版本里没有自动更新，要手动装一次

- 什么 tag 都打包发布。tag 是版本号（`v1.2.3`、`1.2.3` 这样开头的）时要和 `src-tauri/tauri.conf.json` 里的版本号一致，不一致的不打包：忘了改版本号就打 tag 时，安装包会是上一版的版本号
- Latest（[releases/latest](https://github.com/whr819987540/todolist/releases/latest)）指向版本号最大的 tag，按版本号比较（v0.10.0 比 v0.9.0 新，v1.0.0-beta 比 v1.0.0 旧），不看发布的先后：补打旧的 tag、几个 tag 一起推送时先打完的是新版，Latest 也不会落到旧版上。每次发布后按全部 release（草稿、在网页上标成预发布的除外）重新算一遍，在网页上手动改了的下次发布时改回去
- 重新打包某个已有的 tag（构建失败过、tag 推送得比这个 workflow 早）：在 Actions 页面重新运行，或 `gh workflow run release.yml -f tag=v0.2.0`。这个 tag 已经有 release 时只替换安装包和 `latest.json`，不改标题和说明
