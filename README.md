# 待办清单

基于 Tauri 2 + React + Ant Design 的 Windows 桌面待办管理软件，按「工作区 → 项目 → 待办」三级组织，项目下还可以建一层子项目。

## 功能

- **三级结构**：首页列出全部工作区；进入工作区后左侧是可折叠的树（工作区、项目两级都能折叠），右侧显示概览或待办内容
- **子项目**：右键项目（或项目概览、侧栏顶部的「新建」）选「新建子项目」，在项目下再分一层（子项目里不能再建）；父项目自己也能直接放待办。子项目就是项目文件夹里的子文件夹，在侧栏里缩进列在父项目下面、它自己的待办前面，各自可以折叠。父项目的未完成数、完成进度包括子项目里的待办，项目概览上面列出子项目的卡片；父项目改名后子项目、标签、编辑位置都跟着走，删除父项目连同子项目一起进回收站；在左侧列表里按 ← 从子项目回到父项目
- **进入工作区**：从首页点进某个工作区时，直接打开上次在这个工作区打开的待办；还没打开过待办时显示工作区概览
- **拖动移动**：按住左侧列表或项目概览里的待办，拖到左侧的另一个项目上松开，就移到那个项目里；同时显示了几个工作区时，也能拖到其他工作区的项目里。按住左侧列表或概览里的项目，拖到左侧的另一个项目上，放进去成为它的子项目；拖到工作区那一行上，移到这个工作区的顶层（子项目这样移出来），都可以跨工作区，整个项目连同待办（和子项目）移过去（那里已有同名项目、有子项目的项目放进别的项目时不能放）。右键项目的「移动到」能去的地方一样。拖到折叠起来的工作区上停一会儿会自动展开，拖到列表上下边缘会自动滚动，按 Esc 取消
- **开屏**：打开软件时默认显示首页；在「设置 → 常规」里可改成「回到上次的位置」，恢复上次左侧选中的工作区和右侧打开的待办（下次启动时生效）
- **同时查看多个工作区**：点侧栏顶部的工作区名，勾选要显示的工作区（可多选、全选，或「仅显示」某一个），左侧会同时列出这些工作区的项目和待办；选中的工作区会记住，下次进入时恢复
- **后退 / 前进**：用鼠标侧键的后退键、前进键在看过的地方之间来回（首页、工作区概览、项目概览、待办），和浏览器一样；只记这次运行期间的
- **键盘操作**：Alt+← / → 在左侧列表和右侧编辑区之间切换，Alt+↑ / ↓ 在左侧的工作区、项目、待办之间上下移动；焦点在右侧的待办里时，Alt+← / → 切到左边 / 右边的标签（最左边的标签上 Alt+← 仍回到左侧列表，最右边的标签上 Alt+→ 仍把焦点放进正文），Alt+↑ 关掉这个标签
- **标签页**：右侧上方一排标签，可以同时打开多条待办，点标签来回切换，切回来时光标、选中的文字、滚动位置都和离开时一样，焦点直接在正文里，接着打字就行
  - 和 VS Code 一样：单击（或用方向键移到）的待办先开在「预览」标签里（标题斜体），再打开别的会替换它，浏览列表时标签不会越开越多；改了标题或正文、双击左侧的待办、双击标签后一直留着。新建的待办直接开在固定的标签里
  - Ctrl+Tab / Ctrl+Shift+Tab 切到下一个 / 上一个标签；×、鼠标中键或 Ctrl+W 关掉（先保存），右键标签可以关闭其他的、右侧的、全部；按住标签左右拖动调整顺序（Esc 取消）；有没保存的修改时标签上 × 的位置显示圆点
  - 打开着哪些标签记在数据目录里，下次打开软件还在；工作区 / 项目改名、待办移动后跟着走，删除后关掉。只显示侧栏里选中的工作区的标签
- **待办条目**：左侧显示标题；没有标题时显示正文开头（按侧栏宽度自动截断）。每条带完成勾选框、创建时间、最新修改时间，悬停可看完整时间
- **批量操作**：在左侧列表里 Ctrl+单击加选、Shift+单击选中一段，右侧显示批量操作：一起标记完成 / 未完成、置顶、设置优先级、添加 / 移除标签、移动到其他项目、删除；也可以右键选中的待办，或把它们一起拖到左侧的其他项目上。Esc 取消选择，Delete 删除
- **回收站**：删除的工作区、项目、待办先放进软件的回收站，删除后的提示里可以「撤销」；首页头部或侧栏底部的「回收站」里可以恢复到原来的位置（原来的项目、工作区不在了会重新建，名字被占用了加「（恢复）」）、彻底删除或清空。放满 30 天的、彻底删除的移到 Windows 回收站
- **完成记录**：首页头部或侧栏底部的「完成记录」按完成日期列出完成了的待办——今天、昨天，再往前按日期（「10月7日 星期三」），组里后完成的在前，以前的版本没记下完成时间的在最后的「完成时间不详」；每条带着优先级的小旗子和标签（同侧栏）；上面是时间范围（最近 7 天 / 30 天 / 全部，记在本机）、按标题、项目和标签查找（`#标签名` 只按标签找）、今天和这个范围里完成了几条，以及每天完成几条的柱状图（点一根跳到那天）。点一条进入它所在的工作区打开它，右键或行上的按钮「标记为未完成」。首页上看全部工作区；侧栏里默认看选中的工作区，可以切到全部工作区
- **导出**：右键待办（或编辑区上方的「…」）、项目、工作区选「导出」→「导出为 HTML」或「导出为 PDF」。HTML 是一个文件：标题、状态、优先级、标签、所在的位置、时间和渲染后的正文（表格、任务框、代码块、脚注等，正文里写的 HTML 做了安全处理），本地图片嵌在里面，拿到别的电脑上也能看。导出项目、工作区时有封面（待办数、完成进度）和可以点的目录，父项目自己的待办在前、子项目各一章在后，项目和待办的顺序同侧栏（项目手动排序、待办按优先级排时也一样），可以选不含已完成的。总是浅色、A4 宽度，打印时每条待办、每章从新的一页开始。PDF 是用系统的 WebView2 把同样的内容打印出来的（A4，页眉是日期和标题，页脚是页码，网上的图片要联网才印得出来；WebView2 太旧、直接存不成时退回系统的打印对话框，在里面选「另存为 PDF」）。导出前先存盘；默认文件名是标题或项目名，从上次导出到的目录（第一次是「文档」）打开
- **筛选**：侧栏顶部的漏斗按钮（「隐藏已完成」旁边）按标签、优先级筛选：列出侧栏里显示的工作区用到的全部标签和各档优先级（都带条数），可以多选，标签之间「任一」或「全部」；开着时侧栏和项目概览只列符合的待办、没有符合的项目不显示（右侧正在看的照常显示），顶部一行写明筛的是什么，点 × 清除。点侧栏、项目概览、编辑区上方的标签就按它筛选。和搜索、隐藏已完成可以一起用；只记在这次运行期间，筛选时不能拖动调整顺序。弹出框里每个标签后面的「…」可以重命名（改成已有的名字就是合并）、删除这个标签，作用于侧栏里显示的各工作区
- **置顶**：右键待办选「置顶」，它就排在所在项目的最前面（已完成的仍沉底），标题前有图钉
- **优先级**：每条待办可以设成高 / 中 / 低（默认无）：在编辑区上方的下拉、右键「优先级」或多选后「设置优先级」里改；侧栏和项目概览里标题前面显示小旗子（高红、中橙、低蓝），排序按钮里可以「按优先级」排（置顶的仍在前、已完成的仍沉底）。改优先级不算修改，移动后还在
- **标签**：给待办加上「工作」「等回复」这样的标签（可以有多个），跨项目、跨工作区归类：在编辑区上方点「+ 标签」输入（从用过的标签里联想），或右键待办选「标签…」；侧栏和项目概览里标题后面显示彩色的小标签，同名的标签颜色相同。搜索时也匹配标签名，输入 `#标签名` 只按标签找；点标签按它筛选（见「筛选」）；多选后可以批量添加、移除标签。改标签不算修改，移动、恢复后还在
- **手动排序**：在左侧列表或项目概览里把待办拖到同一项目的另一条待办上方 / 下方，调整它的位置，这个工作区随即改成手动排序（排序按钮里可以换回）；新建的待办排在最前面
- **项目的顺序**：项目默认按名字排；在左侧列表里把项目（或子项目）拖到另一个项目那一行的上沿 / 下沿，就放在它前面 / 后面（插入线标出位置），这个工作区的项目随即改成手动排序；拖到别的一层（子项目拖到两个顶层项目之间、项目拖到两个子项目之间、拖到别的工作区的项目旁边）是移过去放在那里，拖到行中间照常是放进去成为子项目。新建的、移进来时没指定位置的排在后面，改名后位置不变；排序按钮里「项目顺序」可以换回按名称（顺序留着，换回手动排序时恢复）。顺序记在数据目录里（`.projects.json`），网盘同步、换电脑都跟着走；概览的卡片、「移动到」、快速记录选项目的列表也按这个顺序
- **正文编辑**：右侧编辑 Markdown；右键待办可「用默认程序打开」，交给系统关联的 Markdown 软件
  - **实时渲染**（默认，类似 Typora）：标题、加粗、斜体、删除线、下划线、行内代码、链接、图片、表格、引用、列表、任务框、分隔线、代码块显示成渲染后的样子，光标移到哪里，哪里显示原文；点任务框直接勾选
  - **源码模式**：显示全部 Markdown 标记，只做语法高亮
  - 按 Ctrl+/ 或点状态栏上的「实时渲染 / 源码模式」切换，每条待办分别记住；没切换过的待办用实时渲染（以前的版本里选了源码模式的，沿用源码模式）。两种模式都只改变显示，文件按原样保存，不会被重新排版
  - **图片**：在正文里 Ctrl+V 粘贴截图、从浏览器复制的图片，或者从资源管理器把图片文件拖进来（拖动时有一条竖线标出放在哪里），复制一份存在项目文件夹的 `.assets\{待办 id}\` 里，正文里写成相对地址 `![说明](.assets/…)`，用 Typora、VS Code 打开 .md 也能显示。实时渲染时显示成图片（宽的缩到编辑区的宽度，显示不了的写明原因），光标所在的那一行显示原文；别处的本地图片（相对路径、绝对路径）和网络图片也能显示。图片跟着待办移动、进出回收站，「另存为新待办」时复制一份
  - **表格**（GFM 表格）：实时渲染时光标不在表格里，整个表格显示成渲染后的样子（表头加粗，按 `:---:` 这类分隔行对齐，格子里的加粗、行内代码、链接、图片也渲染），很宽的在编辑区里横向滚动；单击格子光标放进那一格的原文里，表格显示原文以便修改。列表、引用里的表格显示原文；按 Ctrl+T 插入一个空表格
  - 按住 Ctrl 单击链接用浏览器打开；回车自动续写列表；在列表里按 Tab / Shift+Tab 把这一项（连同子项）缩进成上一项的子项 / 提到上一级，有序列表自动重新编号；不在列表里时 Tab 插入两个空格
  - **编辑快捷键**默认和 Typora 一样：Ctrl+B 加粗、Ctrl+I 斜体、Ctrl+U 下划线、Ctrl+K 超链接、Ctrl+1～6 标题、Ctrl+Shift+[ / ] 有序 / 无序列表、Tab / Shift+Tab 缩进列表、Ctrl+D 选中当前词等，完整列表见下文「快捷键」；都可以在「设置 → 快捷键」里改成自己习惯的按键。再按一次取消；只增删选中处的 Markdown 标记，不会重排别处的写法
  - **大纲**：正文里有 2 个以上标题时，右侧列出标题，点一下跳过去，正在看的那一节高亮；点状态栏的「大纲」或按 Ctrl+Shift+1 显示 / 隐藏
  - **查找 / 替换**：按 Ctrl+F 在正文里查找，输入时直接跳到最近的结果，显示第几个 / 共几个，Enter / Shift+Enter（或 F3 / Shift+F3）找下一个 / 上一个，可以区分大小写、全字匹配、用正则；Ctrl+H 展开替换，逐个或全部替换；Esc 关闭查找框
  - 切换回某条待办时，光标和滚动回到上次编辑的地方，离开时选中的文字仍然选中；正文在外部被改过时按光标前后的文字找回位置，被大幅修改、找不到时回到开头
  - 切到别的待办再切回来，仍能用 Ctrl+Z / Ctrl+Y 撤销、重做之前的修改（只在这次运行期间；正文在外部被改过时从头记起）
  - 代码块：输入 ```语言 后回车会自动补上结尾的 ```；在代码块里按 Ctrl+Enter，或在文末代码块的最后一行按 ↓，跳出代码块（缺结尾的 ``` 时自动补上）
- **保存**：在「设置 → 保存」里修改，立即生效
  - auto save（默认关闭）：开启后，编辑器失去焦点、窗口失去焦点（包括隐藏到托盘）时立即保存，有修改时还定时保存（默认 3 分钟，可设 1 秒到 60 分钟；从第一处未保存的修改开始计时，继续输入不会推迟）
  - 不论开没开，Ctrl+S 立即保存，切换待办、从托盘退出前总会保存（存不上时自动另存为新待办，见下文「外部修改感知」），重命名、移动、删除、用默认程序打开前也总会先保存（存不上时先不做，等你处理完冲突对话框或保存失败的问题）
  - 关闭 auto save 时，失去焦点、隐藏到托盘都不保存；但修改后一直没保存的，满 1 小时会自动保存一次（从第一处未保存的修改开始计时，藏在托盘里时也照样），免得在托盘里挂好几天的程序把改动一直留在内存里
  - 用输入法打字时，拼音还没上屏不算修改，不会被存进文件
- **托盘常驻**：点窗口的关闭按钮只会隐藏到系统托盘，程序继续运行；左键单击托盘图标恢复窗口，右键托盘图标选「退出」才真正退出（会先保存正在编辑的内容；有修改存不下来时不退出，先问你）
- **开机自启**：在「设置 → 常规」里打开，登录 Windows 后自动运行，默认只在托盘里、不弹出主窗口（可以改成显示）；只对这台电脑生效，在任务管理器的「启动应用」里也能关掉，卸载时自动删掉启动项
- **全局快捷键**：默认 Ctrl+Alt+T，在任何程序里按下都能呼出主窗口，主窗口在前台时按下则隐藏到托盘；点右上角的设置按钮可修改、恢复默认或不使用
- **快速记录**：在任何程序里按 Ctrl+Alt+N（或托盘菜单的「快速记录」）弹出一个小输入框，第一行写标题、后面写正文，Enter 存进「收件箱 / 快速记录」（不在时自动建，可以改成别的项目），Ctrl+Enter 存好后在主窗口里打开；Esc 或点到别处关掉，没存的留着
- **待办快捷键**：选中某条待办时，Ctrl+Alt+D 标记完成 / 未完成，Ctrl+Alt+O 用默认程序打开；同样可在设置里修改
- **数据备份**：在「设置 → 备份与恢复」里把全部待办数据（各工作区、项目、待办正文、项目的顺序、正文里的图片和界面状态，不含回收站、设置和密码）打包成 `TodoList-data-年月日-时分秒.zip`，存到本地或上传到 WebDAV；恢复时选本地的备份 zip 或 WebDAV 上的数据备份，确认后用备份替换现在的全部待办数据（替换前先把现在的自动备份成 `…-恢复前.zip`，回收站不动），界面重新加载
  - **自动备份**（默认开启）：启动时和运行期间（藏在托盘里也照常）检查，距上次满 24 小时、数据有变化时备份到 `%USERPROFILE%\TodoList-backups`（可以换目录），只留最近 10 份（可设 1–100），可以同时上传到 WebDAV；失败了不弹窗，在设置里显示原因
- **设置备份**：在「设置 → 备份与恢复」里把设置打包成 `TodoList-settings-年月日-时分秒.zip`，可以存到本地（默认存在数据目录里，也可以另选位置），也可以上传到 WebDAV 服务器（如坚果云）；恢复时可从服务器上的备份列表选择，也可选择本地的备份 zip（默认从数据目录里找，从 WebDAV 下载的也行）。备份只含设置（包括改过的快捷键、自动备份的设置），不含待办数据；拿错了数据备份时会提示
- **字号**：在「设置 → 外观」里分别调整左侧列表（工作区、项目与待办）和右侧待办编辑区的字号，立即生效；编辑时按住 Ctrl 滚动鼠标滚轮可快速调整编辑区字号，点状态栏上的字号恢复默认
- **主题**：浅色、深色或跟随系统（默认），点首页或侧栏顶部的主题按钮、或在「设置 → 外观」里切换，窗口标题栏跟着变
- **编辑区背景色**：待办编辑区默认是护眼米色，可在「设置 → 外观」里换成白色，或选「自定义」输入 RGB 数值设置任意颜色；深色模式下编辑区始终是深色背景
- **全局搜索**：首页可跨全部工作区搜索（Ctrl+Shift+F）工作区、项目和待办（标题与正文全文，命中在正文里的显示关键字附近的一段），点击结果直接打开
- **外部修改感知**：运行期间监听数据目录，网盘同步下来的、别的程序保存的、在资源管理器里增删改名的，窗口一直在前台时也在半秒左右自动刷新（侧栏、首页、概览和打开着的待办；藏在托盘里时等显示出来再刷新），切回窗口时也会刷新；软件自己保存时不会因此重新加载。打开着的待办没有未保存的修改时直接换成外部的内容（光标留在原来那段文字处）；若两边同时改了同一条，立即弹窗让你选择：放弃自己的修改重新加载、用自己的内容覆盖，或「另存为新待办」——两份都保留，你的修改存成同一项目里标题带「（我的版本）」的新待办并打开它，原来这条换成外部改过的内容（外部只是把同样的内容重写了一遍时什么都不做）。没来得及选就切到别的待办、关了标签、退出了，或者切走时才发现外部改过、待办或项目在外部被删了，会自动另存为「（我的版本）」的新待办并提示它的标题（原来的项目不在了时存到快速记录存到的项目），不会悄悄丢掉
- **隐藏已完成**：侧栏顶部的眼睛按钮里，「隐藏已完成的待办」和「隐藏全部完成的项目」（里面有待办而且全都完成了的项目，连同其中的待办不显示；空项目不算）各自开关，每个工作区各自记住。右侧正在看的项目不藏，切走 1 秒后才藏（比双击间隔长，在它下面的项目里双击时下面的行不会在两下之间上移）；搜索时不藏；工作区下面显示「已隐藏 N 个全部完成的项目，显示」。只影响侧栏，工作区概览、「移动到」等照常列出全部项目
- 侧栏搜索（Ctrl+Shift+F，在选中的工作区里查找标题和正文全文）、隐藏已完成、五种排序（创建时间、修改时间、标题、优先级、手动）（这两项每个工作区各自记住，选中多个工作区时作用于右侧正在显示的那个；排序按钮里还有项目的顺序：按名称 / 手动排序）、在项目间移动待办（右键「移动到」，同时显示了几个工作区时按工作区分组列出它们的项目，和拖动一样能移到其他工作区）、侧栏宽度可拖动

## 数据存储

所有数据保存在用户目录下的 `%USERPROFILE%\TodoList`：

```text
TodoList\
  {工作区}\
    {项目}\
      .todos.json            标题、完成状态、置顶、标签、优先级、手动排序的位置、创建/修改/完成时间
      20260926-153012.md     待办正文，一条待办一个文件
      .assets\               正文里的图片（粘贴、拖进来的），一条待办一个子目录：.assets\{待办 id}\{文件名}
      .projects.json         父项目里子项目的顺序（手动排序时）
      {子项目}\              项目文件夹里的子文件夹是子项目（只有一层），里面同样是 .todos.json、.md 和 .assets
    .projects.json           顶层项目的顺序，和这个工作区的项目是不是手动排序
  .settings.json             应用设置（快捷键和改过的编辑快捷键、主题、字号、编辑区背景色、保存方式、开屏方式、开机自启时是否显示主窗口、快速记录存到哪个项目），设置备份的内容就是这个文件
  .webdav.json               WebDAV 服务器地址、用户名、远程目录（密码存在 Windows 凭据管理器）
  .state.json                界面状态：选中的工作区、上次的位置、各工作区上次打开的待办、右侧打开着的标签、各待办的编辑位置和编辑模式
  .recycle\                  软件的回收站，删除的东西先放在这里，30 天后移到 Windows 回收站
    20261004-153012-123\     一项一个目录：entry.json（原来在哪里、待办的标题和完成状态等）和删除的文件 / 目录（待办的图片在 .assets\{待办 id}\ 里）
  TodoList-settings-*.zip    设置备份到本地时默认存在这里（选择恢复文件时也从这里开始找）
  .restoring-年月日-时分秒\  恢复待办数据时的临时文件夹（解压出来的备份、换下来的原来的数据），恢复完就删掉
TodoList-backups\            待办数据的自动备份（数据目录旁边，可以在设置里换别的目录），手动备份、恢复数据的对话框也从这里打开
  TodoList-data-20261009-153012.zip           一份数据备份：各工作区文件夹和 .state.json，外加说明 backup.json
  TodoList-data-20261009-160000-恢复前.zip    恢复数据前自动备份的原来的数据，不算在「保留最近 N 份」里
```

- 标题单独存在 `.todos.json` 里，正文存在 `.md` 文件里
- `.todos.json` 里每条待办一项：`id`（就是 .md 的文件名）、`title`、`done`、`createdAt` / `updatedAt` / `doneAt`，和只在用到时才写的 `pinned`（置顶）、`tags`（标签，如 `["工作", "等回复"]`）、`priority`（优先级：高 3、中 2、低 1）、`order`（手动排序的位置）。置顶、标签、优先级、顺序不算修改，改了不变修改时间；手改得不合规则的标签、优先级读的时候去掉
- 直接往项目文件夹里放 `.md` 文件，软件会自动识别为新待办（文件名作为标题）；在项目文件夹里建文件夹就是建子项目（子项目里的文件夹不算，`.` 开头的不算）
- 项目的顺序每一层一个 `.projects.json`，放在那一层的文件夹里（工作区文件夹里的是顶层项目的，父项目文件夹里的是它的子项目的），如 `{"version": 1, "manual": true, "order": ["需求", "日常"]}`：`order` 是项目的名字从前到后（不分大小写，没列出的排在后面），`manual` 只看工作区文件夹里的，是这个工作区的项目手动排序（换成按名称时顺序留着）。没调整过顺序时没有这个文件；手改坏了的当成没有，照常按名字排。改名、移动、删除项目时跟着改，不算修改
- 正文里粘贴、拖进来的图片存在项目文件夹的 `.assets\{待办 id}\` 里（拖进来的保留原名，粘贴的叫 `图片-年月日-时分秒.png`），正文里写成相对于 .md 的地址。附件目录不算子项目，里面的 .md 不算待办。移动待办时附件目录跟着走（目标项目里重名、换了 id 时目录改成新 id，正文里的链接跟着改，.md 的修改时间不变）；删除时连同 .md 放进回收站的同一项；「另存为新待办」时复制一份给新的那条。显示本地图片经 Tauri 的 asset 协议：数据目录整个放开，数据目录以外的图片在正文里用到时只放开那一个文件（只放开图片）
- 界面状态、标签、快速记录存到哪里等处记的项目是路径：顶层项目是名字，子项目是「父项目/子项目」
- 正文按 UTF-8 保存；放进来的 GBK（ANSI）或带 BOM 的 UTF-16 文件也能正常显示，在软件里改过后转存为 UTF-8；认不出编码的文件只读显示，需要修改时用默认程序打开
- `.todos.json` 损坏时会备份为 `.todos.json.broken-时间戳` 并重建，正文不受影响
- 运行期间监听整个数据目录：在外部（网盘同步、别的程序、资源管理器）增删改名了工作区、项目文件夹、`.md`、`.todos.json` 或 `.projects.json` 时自动刷新；`.` 开头的（`.state.json`、设置文件、保存时的临时文件 `.名字.tmp`、图片的附件目录 `.assets` 等，`.recycle` 只刷新开着的回收站）、直接放在数据目录和工作区文件夹里的文件（如设置备份的 zip）、项目里不是 `.md` 的文件不算。数据目录在不支持变化通知的网络盘上时，只在切回窗口、按 F5 时刷新
- 删除的工作区 / 项目 / 待办先进软件的回收站（`.recycle`），可以撤销、恢复；在回收站里彻底删除、清空或放满 30 天的连同说明进入 Windows 回收站（名字是标题加 id；从 Windows 回收站还原后回到 `.recycle`，又能在软件里恢复；Windows 回收站不可用时移到数据目录下的 `.trash`）
- 待办数据的备份包（`TodoList-data-*.zip`）里是数据目录里的各工作区文件夹（项目、子项目、待办正文、`.todos.json`、项目的顺序 `.projects.json`、图片的附件目录 `.assets` 等，保存时的临时文件 `.名字.tmp` 除外）和 `.state.json`；不含 `.recycle`、`.trash`、设置文件、WebDAV 设置和数据目录里的别的文件。`backup.json` 记着类型（`data`，设置备份里的是 `settings`）、软件版本、备份时间、工作区数和待办数、数据的指纹（各文件的路径、大小、修改时间，`.state.json` 除外、`.projects.json` 和图片也算，自动备份据此判断数据变没变）和各文件、文件夹的修改时间（恢复时改回去）。可以直接用资源管理器打开看
- 恢复数据时先解压到数据目录里的 `.restoring-…`、检查过路径（`..`、绝对路径、盘符等都不行），拿着存储层的锁把现在的数据打包成 `…-恢复前.zip`，再把工作区和 `.state.json` 换成备份里的（只是改名，很快）；中途失败时换回原来的。万一程序在替换中途退出，原来的数据在 `…-恢复前.zip` 和 `.restoring-…\old` 里
- WebDAV 密码保存在 Windows 凭据管理器（普通凭据 `webdav.com.whr.todolist`），不写进任何文件，也不会进入备份包
- 访问 WebDAV 时使用 Windows 的代理设置（或环境变量 `HTTPS_PROXY`），代理例外和 `NO_PROXY` 里的地址直连

界面状态里和数据有关的记在数据目录的 `.state.json`，跟着数据走（换电脑、重装系统后还在；数据目录用网盘同步时一起同步，几台电脑同时开着时以最后写的为准）：侧栏选中的工作区，各工作区上次打开的待办，上次停在哪里（开屏「回到上次的位置」用），右侧打开着的标签（顺序、哪个是预览标签），各待办的编辑位置和编辑模式（各最多记 300 条，最久没动过的先忘掉；编辑模式只记切换过、和默认不一样的）。改动后 5 秒内写盘，隐藏到托盘、退出前立即写；以前的版本记在 localStorage 里的，第一次启动时搬过来。

其他界面偏好只记在本机（WebView2 的 localStorage）：侧栏宽度，各工作区的折叠状态、排序和隐藏已完成（已完成的待办、全部完成的项目；还没单独设置过的工作区沿用以前不分工作区时的设置），是否显示大纲，完成记录的时间范围，上次导出到的目录。导出的文件存在导出时选的地方，不在数据目录里。各待办的撤销记录（最多 50 条）和后退 / 前进的记录（最多 100 处）只在这次运行期间记在内存里。

测试时可用环境变量 `TODOLIST_DATA_DIR` 指定其他数据目录；自动备份默认的目录跟着变成它旁边的「目录名-backups」（如 `%TEMP%\todolist-test-backups`），不会写进真实的 `TodoList-backups`。

## 快捷键

快捷键分两类：应用快捷键操作软件本身，其中三个可以在「设置 → 快捷键」里修改；编辑快捷键只在待办正文里使用，默认按键与 Typora 相同，除了几个固定按键，都可以在「设置 → 快捷键 → 编辑快捷键」里修改、恢复默认或不使用。所有快捷键之间不能重复，设置时会提示。

### 应用快捷键

| 快捷键 | 作用 |
| --- | --- |
| Ctrl+N | 在当前项目新建待办（首页为新建工作区） |
| Ctrl+S | 立即保存（不受 auto save 开关影响） |
| Ctrl+Shift+F | 搜索（首页跨全部工作区，侧栏里搜索选中工作区的待办） |
| Ctrl+F / Ctrl+H | 在正在编辑的待办正文里查找 / 替换（焦点在左侧列表时也行）；没有打开待办时 Ctrl+F 聚焦搜索框 |
| Esc | 在侧栏搜索框里：清空搜索，焦点回到左侧列表 |
| F5 / Ctrl+R | 刷新：从磁盘重新读取（不会像网页那样整页重新加载）；带别的修饰键的不算 |
| Ctrl+Alt+T | 全局快捷键：显示主窗口 / 隐藏到托盘（可在设置里修改） |
| Ctrl+Alt+N | 全局快捷键：弹出快速记录小窗（可在设置里修改）；小窗里 Enter 保存、Shift+Enter 换行、Ctrl+Enter 保存并打开、Esc 关闭 |

| Ctrl+/ | 正文在实时渲染和源码模式之间切换 |
| Ctrl+Shift+1 | 显示 / 隐藏正文右侧的大纲 |
| Ctrl+W | 关掉正显示着的标签（先保存） |
| Ctrl+Tab / Ctrl+Shift+Tab | 切到下一个 / 上一个标签 |
| Ctrl+鼠标滚轮 | 在编辑区调整正文字号 |
| 鼠标后退键 / 前进键 | 回到上一处 / 下一处看过的地方（首页、工作区概览、项目概览、待办） |

| 右键 | 工作区 / 项目 / 待办的操作菜单 |

对话框（回收站、完成记录、设置、确认框等）开着时，除了 Ctrl+S、F5 / Ctrl+R 和全局快捷键，上面这些都不响应，免得在对话框后面新建、切走或改了看不见的待办（判断在 `shortcuts.ts` 的 `inDialog`：焦点在对话框里，或者有对话框开着）。

格式类（加粗到清除格式）：选中的文字已经是这种格式时去掉，否则加上，跨多行时每行分别加；没选中文字时，光标在这种格式里就去掉它，否则插入一对标记、光标放在中间。段落类（标题到代码块）作用于选中的各行，引用、列表、代码块再按一次去掉；插入表格不弹对话框，和上下的文字之间空一行。列表缩进后有序列表跟着重新编号，原本就不是连续编号的（如全写成 `1.`）不动。光标在代码块里时格式、段落类不起作用。

## 开发

需要 Node.js、Rust（MSVC 工具链）和 WebView2（Windows 11 自带）。

在 Linux 上开发（Tauri 在 Linux 上编不了）时怎么验证、怎么交到 Windows 上测，见 [docs/linux-windows-workflow.md](docs/linux-windows-workflow.md)。

```bash
npm install
npm run tauri dev       # 开发调试
npm run build:debug     # 不打安装包的 debug 版 exe，见下文「本机测试用的构建」
npm run build:fast      # 不打安装包、不做 LTO 的优化版 exe，见下文
npm run tauri build     # 正式打包，安装包在 src-tauri/target/release/bundle/nsis/
npm run release         # 打包并安装到本机，见下文
npm run release:fast    # 同上，但用 release-fast profile 构建，快很多
npm run lint            # ESLint 检查前端代码（含 React hooks 的规则），要零错误、零警告
npm test                # 前端单元测试（vitest：标签的规则、联想和颜色、搜索匹配（含 #标签名）、排序（含按优先级）、项目的顺序（按名称 / 手动排序、拖到项目的上沿 / 下沿算放在哪里、放下后那一层的顺序）、按标签和优先级筛选（筛掉哪些项目）、编辑快捷键、列表缩进、代码块、查找、编辑位置、标签页、后退 / 前进、快捷键检查、完成记录的分组、导出的顺序、离开待办时存不上的另存、退出前写盘、数据目录在外部变了时刷新什么、图片的地址和插入、撤销记录接到改了链接的正文上、表格的内容和哪些表格渲染等）
```

- 跑完删掉测试版的开机启动项；彻底删除、清空回收站、放满 30 天的检查会真的移到 Windows 回收站，跑完从那里还原回测试数据目录再一起删掉，不在你的回收站里留东西

注意：

- 跑的时候会弹出测试版的窗口（主窗口会最大化一下），抢前台；别在跑的时候打字。模拟的快捷键不是真的按键，测试版要拿到前台只能靠 tao 的 `set_focus`（模拟按一下 Alt 再 `SetForegroundWindow`）：锁屏了、前台的程序以管理员身份运行（模拟按键送不进去）、或有人正在别的程序里操作时，Windows 不让换前台。`quick`、`regress` 开头试一下，拿不到时「在前台」一类的检查记为跳过并说明原因，不算失败；解锁、换个普通程序在前台、别动键盘鼠标后重跑那个套件即可。别的程序（如会议软件）过一两秒就抢走前台时，快速记录小窗会按设计藏起来，后面的检查可能失败，同样重跑。拖动中窗口失去焦点、或真的鼠标在测试版窗口上动了，页面会按设计取消拖动：`drag` 看到了就松开重拖（打出「↻ 拖动被打断」），最多三次
- 新套件放在 `e2e/suites/`，默认导出 `async function (t)`：`t.main` 是主窗口的页面（`ev` 执行页面代码，`press`（`press(按键, { repeat: 5 })` 是按住不放）、`type`、`click`、`drag` 等），`t.quick()` 是快速记录小窗，`t.win` 是窗口、快捷键、注册表、回收站的操作，`t.check(名称, 是否通过, 附加信息)` 记一项检查，`t.until(条件)` 等到条件成立（每 200 毫秒看一次，最多 5 秒；等页面、文件的变化时用它，别用固定时长的 `sleep`，机器慢时不够），`t.restart()` 重新启动；要在测试数据默认的设置（`fixtures.mjs`）上改几项时导出 `settings`（如 `backup` 的 `{ autoBackup: undefined }`，用软件的默认值）；再加到 `e2e/run.mjs` 的 `SUITES`。页面里能用的工具函数（`row`、`view`、`openTodo`、`menuItem`、`button` 等）在 `e2e/lib/page.mjs`
- 测不到、要手动试的（真的注销 / 重启后的开机自启、安装包的卸载和升级、多显示器、托盘菜单、真实的输入法）列在 `docs/windows-test-checklist.md`

`.github/workflows/e2e.yml`：每次 push 时在 windows-latest 上 `npm ci` 后跑全部套件，加上构建测试版约 9 分钟（Rust 的编译缓存放在 `src-tauri/target/e2e`）。也可以手动跑，只跑其中几个套件：在 Actions 页面点「Run workflow」，或

```bash
gh workflow run e2e.yml --ref <分支> -f suites="batch recycle"
gh run list --workflow E2E --limit 3     # 找到这次的编号
gh run view <编号> --log                 # 看结果；没通过时 gh run download <编号> -n desktop 下载当时整个桌面的截图
```

那台机器是 Windows Server、1024×768 的交互式桌面，以管理员身份运行、没人操作，「在前台」一类的检查都能做。和本机不同、测试里已经处理了的几处：

- WebView2 不认环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`（浏览器进程的命令行里只有 wry 自己的参数），所以远程调试端口写在测试版的配置里（见上文「怎么跑的」）
- `TEMP` 是短文件名（`C:\Users\RUNNER~1\...`），Windows 回收站记的原位置却是长路径：测试数据目录用 `realpathSync.native` 换成长路径
- 机器比较慢：等页面、文件变化的检查用 `t.until(条件)`，别用固定时长的 `sleep`

### 本机测试用的构建

`npm run tauri build` 慢在三处：release 配置开了 `lto = true`、`codegen-units = 1`（最耗时），前端要重新 `tsc && vite build`，最后还要打 NSIS 安装包。测试时按需要跳过：

| 命令 | 产物 | 适用 |
| --- | --- | --- |
| `npm run tauri dev` | 不产出独立 exe，连 Vite 开发服务器（:1420） | 日常改功能：前端改动热更新，不用重新编译；Rust 增量编译 |
| `npm run build:debug` | `src-tauri/target/debug/todo-list.exe` | 要一个能直接双击运行的 exe（前端已打包进去，不需要 Vite）；未优化，性能与正式版不同 |
| `npm run build:fast` | `src-tauri/target/release-fast/todo-list.exe` | 接近正式版的性能：用 `Cargo.toml` 里的 `release-fast` profile，优化级别同 release，但不做 LTO、16 个代码单元并行、增量编译 |
| `cd src-tauri && cargo test` | — | 只改了存储、备份、WebDAV 等 Rust 逻辑，不用启动界面 |
| `npm run release:fast` | 安装包，装到本机 | 频繁装到本机试用，见下文「安装到本机与升级」 |
| `npm run tauri build` / `npm run release` | 安装包 | 发布前完整跑一次 |

参考耗时（本机）：`build:fast` 首次约 2 分钟，之后只改 Rust 代码时几秒到十几秒；`build:debug` 约 30 秒。三种构建的目录（`debug`、`release-fast`、`release`）互不覆盖。

测试构建的注意事项：

- 这些 exe 和安装版是同一个应用（identifier `com.whr.todolist`），单实例插件会把新启动的那个交给已在运行的安装版（把它的窗口调到前台），新启动的自己悄悄退出。要么先从托盘「退出」安装版，要么构建时换一个测试用的 identifier，两者就能同时运行：

  ```powershell
  $env:TAURI_CONFIG='{"identifier":"com.whr.todolist.test"}'; npm run build:debug
  ```

  换了 identifier 的构建在 WebView2 缓存（localStorage 里的侧栏宽度、折叠状态、排序）和凭据管理器里的 WebDAV 密码（`webdav.com.whr.todolist.test`）上与安装版分开，上次的位置、编辑位置和编辑模式在数据目录的 `.state.json` 里，要靠下面的 `TODOLIST_DATA_DIR` 分开；全局快捷键仍然会和安装版冲突，测试版里可以改成别的（如 Ctrl+Alt+Y）。开机自启的启动项名是产品名，测试版里打开、关闭开机自启会改到安装版的启动项；要分开就同时换一个产品名（`$env:TAURI_CONFIG='{"identifier":"com.whr.todolist.test","productName":"待办清单测试"}'`）
- 运行测试构建时用 `TODOLIST_DATA_DIR` 指向临时目录，不要动真实数据：

  ```powershell
  $env:TODOLIST_DATA_DIR="$env:TEMP\todolist-test"; .\src-tauri\target\release-fast\todo-list.exe
  ```

  设置文件也在这个目录里，自动备份默认存在它旁边的 `%TEMP%\todolist-test-backups`。删除的东西先进这个目录里的 `.recycle`，在软件的回收站里彻底删除、清空时仍然进系统回收站
- 调试构建（`npm run build:debug`、`npm run tauri dev`）设了环境变量 `TODOLIST_PDF_PRINT_DIALOG`（随便什么值）时，导出 PDF 不直接存成 PDF，总是退回系统的打印对话框，用来手动试退回的流程（WebView2 是新的，平时走不到）；正式版不认这个变量

代码结构：

- `src-tauri/src/store.rs`：文件存储、元数据对齐、名称校验，软件的回收站（删除时连同说明移进 `.recycle`，恢复、彻底删除、清空、放满 30 天的移到系统回收站；单元测试里「系统回收站」是 `.trash`，不碰用户真正的回收站），界面状态文件 `.state.json` 的读写（内容由前端决定），恢复待办数据时拿着锁把数据目录里的工作区和 `.state.json` 换成备份里的（`replace_data`，中途失败换回原来的），项目的顺序（每一层的 `.projects.json`：`load_workspace`、`list_projects` 给出各项目在它那一层里排第几和工作区是不是手动排序，按名字排要用中文的拼音顺序，在前端排；`reorder_projects`、`set_projects_manual`，改名、移动、删除项目时跟着改）；左侧显示的正文开头（预览）缓存在内存里，按 .md 的修改时间和大小判断是否失效，文件没变就不重新读（窗口每次获得焦点都要重新加载选中的工作区，待办多时读几千个文件开头很慢），缓存是空的时（刚启动）分给几个线程一起读；完成记录（`list_done`）同样扫描元数据，只给列出的已完成待办读正文开头（`scan_project_for`）；全文搜索（`search`）用的正文全文同样缓存在内存里，按同样的办法判断是否失效，软件里保存时直接丢掉那一条（连着很快保存两次、长度又一样时修改时间和大小可能都没变）；缓存不写进任何文件，免得数据目录用网盘同步时多出冲突；每次写完记下写过的文件、文件夹现在的样子（`OwnWrites`，所有写入都经 `atomic_write`、`create_child_dir`、`rename_dir`、`create_dirs` 或就地 `note_own`），监听数据目录时据此认出软件自己写的（见 `watch.rs`）；正文里的图片（附件目录 `.assets/{待办 id}/`）的存放（`save_image` 粘贴的、`import_image` 拖进来的）、找文件（`image_file`），移动、删除、恢复待办时附件目录跟着走，换了 id 时改正文里的链接（`relink_assets`：只改地址开头的 `.assets/{旧 id}/`，修改时间留着原来的），另存为新待办时复制一份（`create_todo_from`）
- `src-tauri/src/watch.rs`：监听数据目录（notify，递归监听，`TODOLIST_DATA_DIR` 指定了别的数据目录时监听它）。一阵变化合起来算一次（静下来 0.3 秒，一直在变时最多攒 2 秒；一批里 200 处以上当成全部变了），按路径算哪些变化算（`classify`：工作区、项目、子项目的文件夹，待办的 `.md` 和 `.todos.json`，工作区、父项目里的 `.projects.json`；`.` 开头的（含恢复待办数据时的 `.restoring-…`）、不是 `.md` 的文件（含导出到数据目录里的 HTML / PDF）、子项目里的文件夹、文件夹自己的修改时间都不算，`.recycle` 单独报），再去掉软件自己写的：`store.rs` 每次写完记下写过的文件、文件夹现在的样子（`OwnWrites`：文件的修改时间和大小、在不在，只认 10 秒内的；文件夹新建、改名、删掉时，里面之前记下的按现在的样子重新记），监听到的变化和记下的一样就是自己写的。有要报的在监听线程里交给 `lib.rs`；没有变化时线程一直等着系统通知
- `src-tauri/src/settings.rs`：应用设置（快捷键、改过的编辑快捷键、主题、字号、编辑区背景色、保存方式、开屏方式、开机自启时是否显示主窗口、快速记录存到哪个项目）的读写和字号、保存间隔的范围
- `src-tauri/src/autostart.rs`：开机自启，读写注册表的 `Run`（启动项名是产品名，Tauri 的卸载程序不是升级时会删掉它）和任务管理器的禁用标记 `StartupApproved\Run`；开机自启时命令行带 `--autostart`，主窗口一开始是隐藏的（`tauri.conf.json` 里 `visible: false`），`lib.rs` 的 `setup` 里按设置决定显不显示。只在托盘里时先不恢复「最大化」（恢复最大化会把窗口显示出来），第一次显示主窗口时再恢复；一直没显示过就退出时，记住窗口状态的插件会按隐藏着的窗口记成没最大化，退出时（`RunEvent::Exit`，插件之后）把主窗口那一项改回启动时的样子
- `src-tauri/src/backup.rs`：设置备份包的打包、解包、命名和读本地的备份文件；两种备份包共用的说明文件 `backup.json`（据此认出拿错了的备份）、数据备份的文件名，WebDAV 上的备份列表（两种都列，标明是哪种）
- `src-tauri/src/data_backup.rs`：待办数据的备份与恢复。打包时列目录、读每个文件都拿一下存储层的锁（`Store::locked`，免得和保存、改名同时进行；Windows 上文件夹里有文件开着时这个文件夹改不了名），读的时候文件没了说明数据在变，从头再来；先写成 `.名字.tmp`，写完再改名。恢复时检查路径、解压到 `.restoring-…`、改回修改时间，再交给 `Store::replace_data` 拿着锁先备份现在的、再换。自动备份的判断（满 24 小时、指纹变了）、只留最近几份（本地和 WebDAV），默认的备份目录和检查（不能在数据目录里面），这次运行期间的结果和「同时只做一件」（`BackupJobs`）；单元测试用 `webdav.rs` 里本机起的假 WebDAV 服务器
- `src-tauri/src/export.rs`：导出成 HTML（导出 PDF 时 `lib.rs` 的 `print_pdf` 把同样的 HTML 打印出来）。前端给出导出哪些待办、什么顺序（侧栏的 `sortTodos` 排好的，Rust 端不再排），这里按顺序从磁盘读出来（`collect`），渲染成一个文件（`render`：封面、目录、各节，样式写在里面，总是浅色、打印时每条待办、每章分页；每节的元信息里有优先级和标签，标签的颜色用 `tag_color`，和前端 `tags.ts` 的 `tagColor` 同一个算法，两边的单元测试用同一组例子）；正文用 pulldown-cmark 按 GFM 渲染，网址、邮箱照编辑器（lezer）的规则变成链接，脚注挪到每一节末尾；渲染结果连同正文里写的 HTML 交给 ammonia 做安全处理；本地图片（相对于 .md 所在文件夹、绝对路径、file:///）读进来嵌成 base64 的 data URI，按文件头定类型；默认文件名（`file_name`：去掉不能用的字符、截短、避开保留名称）
- `src-tauri/src/webdav.rs`：WebDAV 连接配置、密码存取、客户端（含代理处理；数据备份下载时边收边写进文件，上传、下载的超时放宽到 30 分钟）
- `src-tauri/src/lib.rs`：Tauri 命令、打开外部程序和链接、系统托盘、全局快捷键（显示 / 隐藏主窗口和快速记录两个，按下时按 `GLOBAL_KEYS` 找是哪个）、快速记录小窗（label `quick`，第一次用时建，启动 3 秒后也先建好；之后藏起来留着；`skip_taskbar` 只去掉任务栏按钮，每次显示后再标成工具窗口（`WS_EX_TOOLWINDOW`），Alt+Tab 里也没有；WebView2 的参数（`additionalBrowserArgs`）沿用主窗口配置里的；存好后给主窗口发 `data-changed`、`open-todo` 事件）、监听数据目录（`setup` 里 `watch::start`，建不起来时只在标准错误输出里记一行；监听到的变化经 `data-changed` 发给主窗口，带上变了什么（`DataChanged`：`all`、`paths`、`recycle`），主窗口藏在托盘里时攒着、`show_main_window` 时一起发）、窗口图标、本地备份、恢复、导出时的文件对话框（tauri-plugin-dialog，只在 Rust 端调用，前端没有对话框的权限；设置的从数据目录打开，待办数据的从自动备份目录打开，导出的从上次导出到的目录或「文档」打开）、自动备份的线程（启动 5 秒后检查一次，之后每 10 分钟，改了自动备份的设置、恢复了设置时马上检查；有了结果给主窗口发 `auto-backup`），打包、解压、导出放到后台线程里（`spawn_blocking`）；导出完的「打开」「在文件夹中显示」只认这次运行期间导出过的文件；导出 PDF（`print_pdf`）：把 HTML 写成临时文件，在后台线程里建一个看不见的窗口（label `export-pdf-序号`，记住窗口位置的插件不管它，WebView2 的参数沿用主窗口的）加载它，加载完（`on_page_load`，最多等一分钟）经 `with_webview` 拿到 WebView2 的 `ICoreWebView2_7::PrintToPdf` 打印（A4、页边距 15 毫米、背景色、页眉页脚，webview2-com / windows-core 的版本和 wry 用的一致），做完关掉窗口、删掉临时文件，同时只打印一份；打印之前先看选的位置能不能写（`export::check_writable`；试写的空文件删掉后记成软件自己写的，选在数据目录里时监听不刷新），不能写就直接报错。PrintToPdf 做不成（WebView2 太旧、打印出错）时退回系统的打印对话框（`show_print_dialog`）：把那个窗口显示出来、执行 `print()`，窗口留着由用户关掉（点关闭按钮时真的关掉，不像主窗口那样藏到托盘），关掉后删掉临时文件，`export_todos` 返回的 `printDialog` 是没做成的原因、正文里的图片（asset 协议在 `setup` 里放开数据目录，`image_file` 再一张张放开数据目录以外的图片；粘贴的图片 `save_image` 直接收请求体里的数据，不经 JSON）
- `src/components/DoneHistory.tsx`：完成记录对话框和打开它的按钮（首页头部、侧栏底部，同回收站）：时间范围、看哪些工作区、查找、统计和按天的柱状图、按天分组的列表（右键菜单用侧栏共用的那个 `useRowPopups`，优先级的小旗子和标签用 `TodoMarks.tsx` 的 `PriorityFlag`、`TagChips`，同项目概览）；数据经 Rust 端的 `list_done_todos` 读，开着时首页 / 侧栏的数据变了、窗口获得焦点、`data-changed`（只是回收站变了的不算）、F5 后重新读。时间范围、分组、日期标签、查找（`#标签名` 同侧栏的搜索，用 `search.ts` 的 `tagQuery`）和统计的规则（按本地时间的自然日）是 `src/doneHistory.ts` 里的纯函数
- `src/components/RecycleBin.tsx`：回收站对话框和打开它的按钮（首页头部、侧栏底部）；`src/components/undo.tsx` 是删除后带「撤销」的提示（`useUndoDelete`），恢复后 Rust 端给主窗口发 `data-changed` 刷新；回收站开着时，`.recycle` 在外部变了（监听到的 `data-changed` 带着 `recycle`）也刷新列表
- `quick.html`、`src/quick.tsx`、`src/components/QuickCapture.tsx`：快速记录小窗，是 Vite 的第二个页面（`vite.config.ts` 的 `rollupOptions.input`），和主窗口共用 `styles.css`、主题和 `webview.ts`（屏蔽网页的右键菜单、刷新等快捷键）；`src/quickCapture.ts` 是它的选项、按键和草稿；主窗口收到 `data-changed` 时刷新（`hooks.ts` 的 `useAppEvent`），收到 `open-todo` 时打开那条待办（`WorkspaceView` 的 `open` 先重新加载再选中）
- `src/settings.tsx`：前端的设置状态；主题、字号、编辑区背景色、保存方式改动立即生效，停顿片刻再存盘。主题交给 `main.tsx` 的 `Root` 应用（它在 antd 的主题配置外面）；字号写进 CSS 变量 `--fs-sidebar` / `--fs-editor`；背景色标在根元素的 `data-editor-bg` 上、自定义颜色写进 `--c-editor-custom`，`styles.css` 在浅色模式下据此给编辑区上色
- `src/theme.tsx`：主题按钮、antd 主题变量同步成 CSS 变量、窗口标题栏跟着切换；本机（localStorage）缓存一份设置里的主题，启动时设置读出来之前先用，免得界面闪一下（以前主题只记在这里，第一次读到设置时搬进设置文件）
- `src/watch.ts`：数据目录在外部变了时 Rust 端发的 `data-changed` 带的内容（`DataChanged`），和据此判断要不要刷新的纯函数：首页（`dataTouched`）、工作区视图（`workspacesTouched`，只看侧栏里选中的工作区）、打开着的待办（`todoTouched`：它的正文文件或所在的项目、工作区文件夹变了时核对磁盘）、开着的回收站（`recycleTouched`）；快速记录存好后等发的 `data-changed` 不带内容，当成数据变了、具体哪里不知道
- `src/hooks.ts`：窗口焦点监听；从资源管理器拖进窗口的文件（`useFileDrag`：Tauri 在 Windows 上接管了系统的拖放，网页里的 drop 拿不到文件，经它的拖放事件拿路径和位置）；收 Rust 端发来的事件（`useAppEvent`），前端自己也能发同名的（`emitAppEvent`，离开待办时另存了一条后让列表刷新）；隐藏到托盘、退出前要写盘的内容登记在这里（隐藏到托盘时正在编辑的待办受 auto save 开关管，设置总是写盘；从托盘退出时都写盘：先存正在编辑的待办，存不上的另存为新待办，再写界面状态和设置，都存好了才退出，有存不下来的、10 秒内没存完的不退出，调出主窗口问用户。Rust 端的 `request_quit` 在前端 5 秒内没接手（`hold_quit`）时才强制退出）
- `src/App.tsx`：首页 / 工作区视图的切换；启动时先读出 `.state.json`，按开屏设置决定显示首页还是回到上次的位置；从首页进入工作区时打开它上次打开的待办；鼠标侧键后退、前进
- `src/search.ts`：全文搜索。侧栏和首页的搜索在前端匹配项目名、标题、正文开头和标签（`matchTodo`；`#标签名` 只按标签找，`tagQuery`，这时不查正文），同时让 Rust 端在正文全文里查（`useContentSearch`，输入停下片刻再查，数据变了重新查），把正文里有关键字的待办也列出来，标题下面显示命中处附近的一段
- `src/filter.ts`：侧栏（和项目概览）的筛选：符不符合（`matchFilter`：标签任一 / 全部，并且优先级）、顶部那一行写的、改筛选的纯函数（勾上 / 去掉、点了某个标签、标签改名删除后跟着改），现在的筛选放在内存里（`useTodoFilter` 订阅，返回首页再进来还在，不跨重启）；筛掉哪些项目在 `components/sidebar/tree.ts` 的 `hiddenByFilter`（同「隐藏全部完成的项目」：右侧正在显示的、刚切走的不筛），弹出框是 `components/sidebar/FilterPanel.tsx`（里面重命名、删除标签的操作在 `workspaceActions.ts` 的 `tags`，经 Rust 端的 `rename_tag`、`remove_tag` 一次改完侧栏显示的各工作区）
- `src/tags.ts`：待办的标签（tag）的纯函数：规整标签名（`cleanTag`，同 Rust 端的 `clean_tag`）、不区分大小写地加上 / 去掉、侧栏里显示的工作区用过哪些（`countTags`）、输入时的联想、颜色（`tagColor`，按名字固定地取 9 种之一，样式在 `styles.css` 的 `.tag-c0`～`.tag-c8`，浅色、深色各一套）；`src/priority.ts` 是优先级的几档和名字；优先级的小旗子、编辑区上方的优先级下拉，标签的显示和编辑区上方的编辑在 `components/TodoMarks.tsx`，选标签的对话框（右键「标签…」、批量添加 / 移除）在 `components/TagDialog.tsx`
- `src/rescue.ts`：离开一条待办（卸载、从托盘退出）时存不上的修改另存为新待办：要不要另存、按什么顺序试存到哪里（原来的项目；不在了时快速记录存到的项目，不在时新建，`create_todo` 带 `createProject`）、提示怎么写；`TodoEditor` 的 `leave` 调它
- `src/navHistory.ts`：后退、前进的记录（首页和工作区里右侧显示过的内容），只在内存里；用键盘在左侧列表里连着移动时只记停下的那一处
- `src/tabs.ts`：右侧标签页的规则（纯函数）：打开时放进预览标签还是固定标签、放在哪里，拖动后的顺序，关掉后切到哪一个，Ctrl+Tab 的下一个，改名、移动后跟过去；标签本身记在 `workspaceState.ts`（`openTodos`），`WorkspaceView` 用 `useSyncExternalStore` 订阅，右侧显示了哪条待办就经 `showTodoTab` 放进标签，标签栏是 `components/EditorTabs.tsx`（拖动标签和侧栏的拖动一样用鼠标事件自己实现）。同一时刻只有正显示着的那个标签建了编辑器，切换标签和切换待办一样重建编辑器，光标、选区、滚动和撤销记录靠按待办记下的编辑位置（`editor/position.ts`）和撤销记录找回；点标签切过去时 `MarkdownEditor` 建好后自己聚焦（开发时 StrictMode 会把编辑器建两次，外层聚焦会落到销毁了的那个上）
- `src/workspaceState.ts`：界面状态，记在 `.state.json` 里的（选中的工作区、各工作区上次打开的待办、上次停在哪里、右侧打开着的标签、各待办的编辑位置和编辑模式；启动时读一次，改动后稍后写盘，隐藏到托盘、退出前立即写）、记在 localStorage 里的（各工作区的折叠状态、排序和隐藏已完成）和记在内存里的各待办撤销记录，工作区 / 项目改名、删除，待办移动、删除时同步（后退、前进的记录也在这时同步）
- `src/exporting.ts`：导出哪些待办、什么顺序（`exportGroups`：项目按 `sortProjects`（这个工作区手动排序时按 `.projects.json` 记的顺序，导出时重新读的 `manualOrder`）、待办按 `sortTodos`（含按优先级），和侧栏同一份规则），确认框里的数目、提示的文字，上次导出到的目录（localStorage）；导出的流程在 `src/components/exportFlow.tsx`（`useExport`：先存盘、存不上就不导出，导出项目、工作区时重新读一遍数据、确认「包含已完成的待办」，`pickExportTarget` 选位置（端到端测试里换成直接返回路径），`exportTodos` 在后台导出，提示带「打开」「在文件夹中显示」；导出 PDF 退回了打印对话框时（`printDialog`）改为提示没做成的原因和怎么存），菜单里的「导出」在 `menus.tsx`，`workspaceActions.ts` 的 `exportTodo` / `exportProject` / `exportWorkspace` 决定要不要先存盘
- `src/dataBackup.ts`：恢复待办数据的流程：先 `flushAll` 保存正在编辑的待办，再 `workspaceState.ts` 的 `suspendUiState` 写掉没写盘的界面状态、之后不再写（内存里的标签、编辑位置稍后写盘会覆盖恢复出来的 `.state.json`），同时 `hooks.ts` 的 `holdDataRefresh` 让 `data-changed`、窗口获得焦点、F5 都不刷新（数据目录正被整个换掉，监听会看到一大批变化，刷新会读到换掉之后的数据、报「工作区不存在」），恢复成功后把结果记在 sessionStorage、`location.reload()`，重新加载后 `App.tsx` 回到首页并显示结果；失败时 `resumeUiState`、放开刷新并发一次 `data-changed`。还有备份、恢复的提示和自动备份状态的文字
- `src/editShortcuts.ts`：编辑快捷键的列表（命令、名称、默认按键、固定按键、分组），设置里改过的盖在默认值上得到现在用的按键；编辑器按它绑定按键，设置界面按它展示和检查重复
- `src/editor/`：基于 CodeMirror 6 的正文编辑器
  - `setup.ts`：组装编辑器（快捷键、Markdown 解析、两种模式的切换）；输入法组合中的改动等上屏后再报告，免得拼音被存盘。Markdown 解析的配置（`markdownSupport`）单元测试也用
  - `editBindings.ts`：把编辑快捷键绑到 `formatting.ts`、`lists.ts` 的命令上，每次按键时按现在的设置查表（改了立即生效），先于 CodeMirror 自带的按键、后于应用快捷键
  - `formatting.ts`：编辑快捷键的命令（行内格式、标题、引用、列表、代码块、选词 / 选行），按语法树和行首的块标记增删原文里的标记
  - `lists.ts`：Tab / Shift+Tab 缩进列表项（按语法树找出列表项和它的上一项、上一级，移动整棵子树后给有序列表重新编号），不在列表里时的 Tab
  - `appearance.ts`：两种模式共用的外观（语法高亮、标题 / 代码块 / 引用的整行样式）
  - `livePreview.ts`：实时渲染，按语法树隐藏标记（含 `<u>` 标签）、替换成列表符号 / 任务框 / 分隔线 / 图片，光标处显示原文（表格在 `tables.ts`）
  - `tables.ts`：实时渲染时的表格：按语法树拆出表头、对齐、各格的内容（`tableModel`）和单击格子时光标放在哪里，光标（选区）不在表格里时整个表格换成 `<table>`。替换的是好几行（块级），CodeMirror 只许从 StateField 里给，编辑器有没有焦点、鼠标是不是按着由事件告诉这个字段
  - `images.ts`：正文里的图片：地址的解析（相对路径、绝对路径、`file:///`、网络图片）、插入的写法（`![说明](地址)`，有空格、括号时写成 `<…>`）、粘贴时剪贴板里算不算图片、实时渲染时显示图片的 `ImageWidget`（经 `ImageResolver` 找文件，记着上次的地址和图片大小，重新显示时不闪）、拖进图片时画出放下的位置；存文件、显示用的地址由 `TodoEditor` 经 Rust 端做
  - `history.ts`：撤销记录接到软件自己改过链接的正文上（移动、另存为新待办后换了 id）：按行找出改了的地方，当成不进撤销记录的修改，撤销记录跟着挪位置
  - `links.ts`：解析链接地址、Ctrl+单击打开
  - `codeFences.ts`：代码块自动补结尾、Ctrl+Enter / ↓ 跳出代码块
  - `outline.ts`：大纲。按语法树找出标题、去掉标记（`outlineItems`），报告正在看的位置（光标在可见区域里时是光标处，否则是可见区域顶部，`trackReadingPos`），跳到标题；大纲面板是 `components/Outline.tsx`，`TodoEditor` 在打字停下片刻后（和字数一起）更新它，正在看的标题变了才重新渲染
  - `find.ts`：正文里的查找 / 替换。搜索状态、匹配高亮和查找替换命令用 `@codemirror/search`，查找框自己实现（中文、第几个 / 共几个、输入时跳到最近的结果）；Ctrl+F、Ctrl+H 由 `WorkspaceView` 经 `TodoEditor` 转过来，焦点不在正文里时也能打开
  - `position.ts`：编辑位置（光标和选区另一端、光标在编辑区里的高度、它们前后的原文），打开待办和外部修改后重新加载时据此找回光标（选区）和滚动
- `src/projects.ts`：项目路径（顶层项目是名字，子项目是「父项目/子项目」，和 Rust 端 `store.rs` 的约定一样）的拆分、显示成「父项目 / 子项目」、排序（`sortProjects`：按名称，或手动排序时按 Rust 端给的各项目在那一层里的位置 `order`，没排过的在后面；子项目跟在父项目后面）、改名移动后跟着改（`reparent`），父项目连同子项目的待办（`deepTodos`）
- `src/components/`：首页（含搜索）、工作区视图、侧栏树（`TreeRows` 的 `ProjectBranch` 也显示子项目，子项目在父项目的分支里、排在它自己的待办前面）、概览、拖动移动（`DragMove.tsx`，用鼠标事件自己实现，没用 HTML5 拖放；放下的位置按侧栏节点上的 `data-drop-ws` / `data-drop-project` 找；指针在同一项目的另一条待办行（`data-sel`，左侧列表和项目概览里都有）上时是调整顺序，`workspaceActions` 的 `reorderTodo` 按现在显示的顺序算出新顺序（`utils.ts` 的 `reorderedIds`）存下；拖项目时指针在另一个项目那一行的上沿 / 下沿（`edgePlace`，各四分之一）是放在它旁边，插入线画在那个项目整块的上面 / 下面，`placeProject` 按那一层现在的顺序（含藏起来的）算出新顺序（`projects.ts` 的 `reorderedNames`），同一层经 `reorder_projects` 存下、先在本机改好（`withProjectOrder`，不重新加载），不在同一层经 `move_project` 带上位置）、编辑器（`TodoEditor` 管定时保存（auto save 关闭时 1 小时兜底）、auto save、冲突（窗口获得焦点、监听到这条的正文文件在外部变了时核对磁盘，内容没变的重写什么都不做，有没保存的修改时立即弹出冲突对话框；含「另存为新待办」：Rust 端 `create_todo` 可以带正文一次建好；离开时存不上的另存为新待办，见 `src/rescue.ts`）和记下编辑位置，打字时不重新渲染，状态栏的字数、行数停顿片刻再算（`utils.ts` 的 `textStats`），粘贴、拖进来的图片经 Rust 端存进附件目录后插入（只读的不插、太大的提示），另存为新待办时让 Rust 端复制一份图片，`MarkdownEditor` 包装 CodeMirror）、设置

  - 侧栏：`Sidebar.tsx` 管树的焦点和键盘操作（↑↓←→、Enter、Alt+方向键），其余在 `sidebar/` 下——`SidebarToolbar`（顶部：返回首页、选中工作区的 `WorkspacePicker`、主题、设置、搜索、新建、排序（待办的排序和项目的顺序）、隐藏已完成、筛选（弹出框 `FilterPanel`，开着时下面一行写明筛的是什么）、全部折叠 / 展开）、`TreeRows`（工作区、项目、待办的行）、`RowPopups`（待办行共用的悬停提示 `TodoTip` 和右键菜单）、`tree.ts`（右侧显示的内容 `Selection`、行上 `data-sel` 的键、折叠状态、计数、「隐藏全部完成的项目」时藏起哪些项目（有子项目时连同子项目一起看），切走后再显示 1 秒的项目怎么记，「全部折叠 / 全部展开」看哪些项目）、`lingering.ts`（给切走后再显示 1 秒的项目计时）

### 安装到本机与升级

```bash
npm run release              # 用当前版本号打包并安装
npm run release -- patch     # 先升版本号（0.1.0 → 0.1.1）再打包安装；也可以是 minor、major 或 0.2.0 这样的具体版本
npm run release:fast         # 同 release，但用 release-fast profile 构建（不做 LTO），参数用法一样
```

`release:fast` 编出来的程序性能接近正式版、体积稍大，适合频繁装到本机试用；安装包在 `src-tauri/target/release-fast/bundle/nsis/`。

`scripts/release.mjs` 依次：

1. 带了版本参数时，改 `package.json`、`package-lock.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 里的版本号（`Cargo.lock` 在构建时自动更新），这几个文件的改动要一起提交
2. `npm run tauri build`（`release:fast` 用 `npm run tauri -- build -- --profile release-fast`）
3. 如果程序正在运行，提示从托盘「退出」并等它退出后再继续。安装程序会直接结束所有名为 `todo-list.exe` 的进程，先正常退出才能保证正在编辑的内容已保存
4. 运行安装包（只显示进度条，不用点下一步），装完自动启动。已经装过时按升级处理：直接覆盖，不先卸载旧版，也不会重建你删掉的快捷方式

程序只装给当前用户，位置是 `%LOCALAPPDATA%\待办清单\`，不需要管理员权限，可以在「设置 → 应用」里卸载。待办数据在 `%USERPROFILE%\TodoList`，安装、升级、卸载都不会动它。

平时请从开始菜单或桌面快捷方式启动安装版，不要直接运行 `src-tauri\target\release\todo-list.exe`：两者是同一个应用，同时只能开一个；而且它运行时文件被占用，再次构建会报拒绝访问（os error 5）。
