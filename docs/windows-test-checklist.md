# Windows 手动测试清单（2026-10 这一批功能）

这批功能在 Linux 上开发：Rust 端的存储、设置、回收站逻辑跑过单元测试，对 Windows 目标做过类型检查（`cargo check --target x86_64-pc-windows-msvc`）；界面在浏览器里用模拟的后端跑过。下面这些要在 Windows 上实际跑一遍才能确认。

## 准备

```powershell
npm install
# 先跑一遍和 CI 相同的检查（GitHub Actions 上也会跑）
npm run lint; npm test; npm run build; cd src-tauri; cargo test; cd ..

# 测试版和安装版分开：换 identifier 和产品名（开机自启的启动项名是产品名），数据放临时目录
$env:TAURI_CONFIG='{"identifier":"com.whr.todolist.test","productName":"待办清单测试"}'
npm run build:debug
$env:TODOLIST_DATA_DIR="$env:TEMP\todolist-test"; .\src-tauri\target\debug\todo-list.exe
```

全局快捷键会和正在运行的安装版冲突：测试时先从托盘退出安装版，或在测试版里把快捷键改成别的。

## 1. 正文里查找 / 替换（Ctrl+F / Ctrl+H）

- [ ] 打开一条长待办，焦点在正文里按 Ctrl+F：正文上方出现查找框，输入时直接跳到光标后最近的结果，右边显示「2/5」这样的计数
- [ ] 焦点在左侧列表、标题输入框里按 Ctrl+F 也能打开；没有打开待办（概览页）时 Ctrl+F 聚焦侧栏搜索框；首页 Ctrl+F 聚焦首页搜索框
- [ ] Enter / Shift+Enter、F3 / Shift+F3 找下一个 / 上一个，到末尾后从头找；Aa（区分大小写）、ab（全字匹配）、.*（正则）三个开关有效，正则写错时显示「正则有误」
- [ ] 用中文输入法在查找框里打字：拼音没上屏时不跳，上屏后才查
- [ ] Ctrl+H 展开替换：「替换」逐个替换，「全部替换」后显示「已替换 N 处」；Ctrl+Z 能撤销替换
- [ ] Esc 关闭查找框、焦点回到正文；选中一段文字再按 Ctrl+F，查找框里是这段文字；切到别的待办再 Ctrl+F，接着用上次查的内容
- [ ] 选中两行再按 Ctrl+F：不拿这两行查，接着用上次的内容；选中一个词再按 Ctrl+H：查这个词，「替换为」里还是上次填的
- [ ] 查 `C:\new\temp` 这样带反斜杠的文字能查到；查找框没开着时按 F3 直接找下一个（用上次的内容），焦点留在正文
- [ ] 查找框开着时用记事本在外部改了正文，切回窗口重新加载后查找框还开着
- [ ] 只读的待办（编码认不出的文件）没有替换那一行
- [ ] 深色模式下查找框、匹配高亮看得清
- [ ] 设置 → 快捷键 → 编辑快捷键：录制 Ctrl+F、Ctrl+H 时提示被占用；「固定按键」里列出了查找、替换、查找下一个

## 2. 全文搜索

- [ ] 侧栏搜索（Ctrl+Shift+F）输入只在正文后半部分（第 200 字以后）出现的词：能搜到这条待办，标题下面显示关键字附近的一段，关键字高亮
- [ ] 首页搜索同样能搜到，结果里显示那一段；点结果打开待办
- [ ] 不区分大小写；放进来的 GBK 编码 .md 里的中文也能搜到
- [ ] 在软件里改了正文、保存后，用新内容能搜到、旧内容搜不到；用记事本在外部改了正文，切回窗口后也按新内容搜
- [ ] 数据多（几百、几千条）时，第一次搜索的耗时可以接受，之后输入很快

## 3. 大纲

- [ ] 有 2 个以上标题的待办，正文右侧显示大纲，按级别缩进，加粗、链接地址等标记已去掉；代码块里的 # 不算
- [ ] 点大纲里的标题跳过去（标题滚到顶部），滚动正文时高亮跟着变；在文末的标题上也能高亮
- [ ] 打字加 / 删标题后，停一下大纲跟着变
- [ ] 状态栏「大纲」和 Ctrl+Shift+1 显示 / 隐藏，重启后记住；窗口拉窄（编辑区不到 700px）时大纲自动不显示

## 4. 开机自启

- [ ] 设置 → 常规 → 打开「开机时自动启动」：注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 里出现「待办清单测试」，值是带引号的 exe 路径加 ` --autostart`
- [ ] 任务管理器 →「启动应用」里能看到它、状态是「已启用」；在那里禁用后重新打开设置，开关显示关闭；在设置里再打开，任务管理器里变回「已启用」
- [ ] 注销 / 重启后自动运行：默认只有托盘图标、不弹主窗口；取消勾选「开机启动后只在托盘里」后，开机时显示主窗口
- [ ] 正常双击启动（不带 --autostart）总是显示主窗口；窗口大小、位置、最大化照常恢复，启动时没有白屏闪一下或窗口跳位置
- [ ] 把主窗口最大化后从托盘退出，开机自启（只在托盘里）：主窗口不会弹出来；点托盘图标显示时是最大化的
- [ ] 关闭开关后注册表里那一项被删掉
- [ ] 安装版：卸载后启动项被删掉；用 `npm run release -- patch` 升级（/UPDATE）后启动项还在

## 5. 快速记录小窗

- [ ] 在别的程序里按 Ctrl+Alt+N：在鼠标所在的屏幕上（多显示器时试一下）弹出置顶的小窗，输入框有焦点、可以直接打字（包括中文输入法）
- [ ] 第一次用时默认存到「收件箱 / 快速记录」，下拉框里注明「保存时新建」；Enter 保存后小窗消失，主窗口里出现「收件箱」工作区和这条待办（第一行是标题、其余是正文）
- [ ] Shift+Enter 换行；输入法组合中按 Enter 只上屏、不保存
- [ ] Ctrl+Enter（或「保存并打开」）：保存后主窗口弹到前台并打开这条待办（主窗口在首页、在别的工作区、藏在托盘里时都试一下）
- [ ] 换「存到」的项目后关掉再打开，还是选的那个；在主窗口里把这个项目改名、移到别的工作区后，小窗里跟着变
- [ ] Esc、点到别的窗口、再按一次 Ctrl+Alt+N 都会藏起小窗，写了一半的内容下次弹出还在（退出程序再开也在）
- [ ] 标题处可以拖动小窗；小窗不出现在任务栏、Alt+Tab 里
- [ ] 托盘右键菜单有「快速记录」，点了弹出小窗
- [ ] 主题：切到深色后小窗也是深色
- [ ] 设置 → 快捷键：「快速记录」在全局快捷键一组里，可以改、恢复默认、不使用；被别的程序占用时有提示。录制任何快捷键时按 Ctrl+Alt+N 不会弹出小窗
- [ ] 设置 → 常规 →「快速记录」里也能改存到哪里
- [ ] 以前把「显示 / 隐藏主窗口」改成了 Ctrl+Alt+N 的设置文件：启动后快速记录显示为「不使用」，没有冲突
- [ ] 启动后马上（3 秒内）按 Ctrl+Alt+N、点托盘「快速记录」也能弹出，程序不会卡住（小窗这时在后台线程里建）

## 6. 置顶

- [ ] 右键待办 →「置顶」：排到项目的最前面，标题前有图钉，编辑区显示「已置顶」；修改时间不变
- [ ] 各种排序下置顶的都在最前；已完成的置顶待办排在已完成里的最前面
- [ ] 移到别的项目后仍然置顶；`.todos.json` 里有 `"pinned": true`，取消后这一项消失

## 7. 手动排序（拖动）

- [ ] 在左侧列表里把待办拖到同一项目的另一条上：上半截显示插入线在上、下半截在下，提示「放在「X」前面 / 后面」；松开后位置变了，提示「已改为手动排序」，排序按钮里选中了「手动排序」
- [ ] 在项目概览的列表里拖动同样有效
- [ ] 已完成的拖到未完成的旁边、置顶的拖到没置顶的旁边：不能放，提示原因；搜索时不能调整顺序
- [ ] 手动排序下新建的待办在最前面；重启后顺序不变；修改时间不变
- [ ] 拖到别的项目上照常是移动（不受影响）

## 8. 批量操作

- [ ] 打开一条待办，Ctrl+单击另一条：两条都高亮，右侧变成「已选择 2 条待办」；Shift+单击选中一段（跨项目也行）
- [ ] 批量标记完成 / 未完成、置顶 / 取消置顶、移动到（同时显示几个工作区时按工作区分组）、删除（先确认）都有效，部分失败时提示失败条数
- [ ] 在选中的待办上右键是批量菜单；按住选中的一条拖到左侧别的项目上，选中的一起移过去
- [ ] Esc 取消选择（右键菜单开着时 Esc 只关菜单）；Delete 删除选中的；Ctrl+Alt+D 把选中的一起标记完成
- [ ] 普通单击、方向键移动、返回首页后多选取消
- [ ] 打开 A、Ctrl+单击 B，把两条一起移到别的项目：右侧不闪「待办不存在」
- [ ] 多选两条后在资源管理器里删掉其中一条的 .md，按 F5：不再显示批量面板，剩下那条也不高亮

## 9. 回收站和撤销

- [ ] 删除待办 / 项目 / 工作区后，提示里有「撤销」，点了恢复到原处；删的是正打开着的待办时，撤销后重新打开它；撤销删除工作区后它重新出现在侧栏
- [ ] 批量删除后一次「撤销」恢复全部
- [ ] 数据目录里出现 `.recycle\{时间}\entry.json` 和删掉的文件 / 目录；它不出现在首页工作区列表、搜索结果里
- [ ] 首页「回收站」按钮、侧栏底部「回收站」都能打开回收站：最近删除的在前，可以按名称查找；「恢复」恢复到原来的位置，标题、完成状态、置顶、创建时间都在
- [ ] 原来的项目 / 工作区已经删了：恢复待办时重新建出来；同名的项目 / 工作区已经有了：恢复的加「（恢复）」
- [ ] 「彻底删除」「清空回收站」：东西进了 Windows 回收站，名字是「标题（时间 id）」；从 Windows 回收站「还原」后，它又出现在软件的回收站里，还能恢复到原处
- [ ] 把某个 entry.json 里的 `deletedAt` 改成 31 天前，重启程序，3 秒后这一项移到了 Windows 回收站；再从 Windows 回收站还原它，重启后它还留在软件的回收站里（不会又被移走）
- [ ] 删除时文件正被别的程序占用（例如项目文件夹开在资源管理器里、.md 开在别的编辑器里不让删的情况）：提示删除失败，数据原样不动
